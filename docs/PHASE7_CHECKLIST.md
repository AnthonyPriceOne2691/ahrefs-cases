# Ф7: что проверить первым же живым ключом

Список составлен заранее, пока предположения свежи. Каждый пункт — гипотеза
из `docs/FINDINGS.md` с готовым способом проверки и с тем, что делать при
расхождении. Цель — закрыть все догадки об API за один заход, а не выяснять
их по одной в течение недели.

**Перед началом:** `AHREFS_PROVIDER=live` ставит человек, не агент
(`AGENTS.md`). Первые запросы делать по **одному** домену, не по списку.

---

## Шаг 1. Квота — бесплатно, поэтому первым (Z2)

```
GET /v3/subscription-info/limits-and-usage
```

- [ ] Ответ содержит ключи `units_limit` и `units_usage`?
- Если имена другие → поправить `_UNITS_LIMIT_KEY` / `_UNITS_USED_KEY` в
  `collect/quota.py`. Тест `test_quota_with_expected_keys_works` обновить на
  реальную форму.
- Признак, что этот пункт пропущен: `preflight` даёт `UNKNOWN` с текстом
  «в ответе нет ключа», и **ни один прогон не стартует**.

## Шаг 2. Форма history-ответа (Z3)

```
GET /v3/site-explorer/metrics-history?target=<домен>&date_from=2025-01-01
    &history_grouping=monthly&mode=subdomains&select=date,org_traffic,org_cost
```

- [ ] Список лежит по ключу `metrics`? (`EndpointSpec.list_key`)
- [ ] В строке есть `date`, `org_traffic`, `org_cost`?
- [ ] Формат даты — `2025-01-01` или `2025-01-01T00:00:00Z`? Оба разбираются.
- При расхождении правится **одна** запись в `collect/endpoints.py`; разбор
  строки один на все endpoint'ы (`live._to_point`).
- Признак пропуска: `AhrefsResponseError` с перечислением пришедших ключей.

Повторить для остальных пяти endpoint'ов — их `list_key` угаданы так же.

## Шаг 3. Стоимость запроса (H1)

- [ ] Заголовки `x-api-units-cost-total`, `-total-actual`, `-row` пришли?
- [ ] Сколько списалось за `metrics-history` с двумя полями? Ожидаем 50.
- [ ] Сколько за `refdomains-history`? Ожидаем 5 (документация называет
      отдельную цену, но и минимум 50 — что из этого правда, знает только API).
- [ ] Зависит ли цена от числа строк? Сравнить запрос за 3 месяца и за 24.
- Модель живёт в одном месте — `EndpointSpec.estimate_units`. При расхождении
  правится там, и смета с журналом становятся верными сразу.
- Автоматический сигнал уже стоит: расхождение сметы с фактом больше
  `AHREFS_ESTIMATE_TOLERANCE_PCT` пишется в лог как `ahrefs_estimate_missed`.

## Шаг 4. Сетка и глубина (H4, H3)

- [ ] Все точки — первые числа месяцев? Иначе в логе `ahrefs_history_not_monthly`.
- [ ] Запросить `date_from` за 24 месяца: сколько месяцев реально пришло?
      Разница пишется как `ahrefs_history_shallower_than_asked`.
- Если глубина меньше 24 — уменьшить `AHREFS_MAX_HISTORY_MONTHS` до реальной,
  иначе проекты с длинным периодом будут молча получать обрезанную историю
  (в вердикте это видно как `history_truncated`, но лучше не создавать случай).

## Шаг 5. Закрытый месяц (H2)

Единственная гипотеза, которую нельзя проверить одним запросом.

- [ ] Запросить историю домена сегодня и через день-два, сравнить значение за
      **текущий** месяц. Меняется — значит текущий месяц не закрыт (наше
      предположение верно).
- [ ] Сравнить значение за **прошлый** месяц в те же два дня. Если меняется и
      оно — предположение неверно, и `cache.closed_through` должен отступать
      на месяц дальше, иначе мы навсегда сохраним неполные данные.

## Шаг 6. Поведение под нагрузкой

- [ ] Сколько запросов в минуту принимает тариф? Настроить `COLLECT_MAX_PARALLEL`.
- [ ] Приходит ли 429 и с каким `Retry-After`? Транспорт повторяет 429, но
      уважать `Retry-After` он пока не умеет — если заголовок есть, добавить.
- [ ] Сколько реально идёт прогон на 100 доменов? От этого зависит
      `COLLECT_RUN_TIMEOUT_SEC`, а от него — порог реапера (инвариант в конфиге).

## После проверки

- [ ] Обновить `docs/FINDINGS.md`: подтверждённые гипотезы уходят из реестра,
      опровергнутые становятся исправлениями.
- [ ] Записать реальную цену прогона на 100 доменов — это метрика приёмки,
      которую заказчик назвал сам.
