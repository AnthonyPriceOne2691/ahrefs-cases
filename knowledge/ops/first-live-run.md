# Правило номер один

**Переключение провайдера в `live` — решение человека.** Разработка идёт на
`AHREFS_PROVIDER=fixture`: записанные и синтетические ответы, без сети и без
расхода квоты. Живой ключ жжёт units заказчика.

# Порядок

Подробный чеклист с ожидаемыми значениями и действиями при расхождении —
`docs/PHASE7_CHECKLIST.md` (в git). Здесь — инварианты порядка:

1. **Сначала бесплатное.** Остаток квоты (`subscription-info/limits-and-usage`)
   стоит 0 units — с него и начинается любой живой заход.
2. **Один запрос перед сотней.** Разведка на одном домене отвечает на пять
   гипотез сразу; именно так была опровергнута модель стоимости.
3. **Смета до старта.** Preflight отказывает до первого запроса — единственное
   место, где отказ ничего не стоит. Проверка по ходу нашла бы нехватку, когда
   часть units уже потрачена.
4. **Расхождение сметы с фактом слышно сразу**: больше
   `AHREFS_ESTIMATE_TOLERANCE_PCT` пишется как `ahrefs_estimate_missed` с обоими
   числами.

# Что заказчик должен знать до прогона

Первичный прогон по ТЗ стоит **около 27 330 units** (273 на домен), а не 10 000,
как планировалось: ошибка была в оценке шага 2. Нужен боевой лимит **от 30 000**.

# Известные ловушки

- **Реапер добивал живой прогон.** Прогон получил собственный лимит времени, и
  порог реапера обязан быть строго больше — это проверяет конфиг на старте
  процесса. Перенося чужой паттерн, переноси и опору, на которой он держится.
- **Пустой ответ ≠ отсутствие истории.** Память о пустоте включается только
  после двух пустых ответов подряд: опечатка в домене и чужая форма ответа
  выглядят так же.
- **Заголовок `x-api-units-cost-total-actual` приходил нулём** при ненулевом
  `-total`: факт расхода берётся не из него одного.
