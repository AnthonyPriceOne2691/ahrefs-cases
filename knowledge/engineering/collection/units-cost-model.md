# Формула

```
стоимость запроса = max(50, строки × (10 × биллингуемых_полей + 1))
```

**Замерено живым ключом 10.09.2026**, не выведено из документации.
Подтверждено заголовком `x-api-units-cost-row`: 21 при двух полях, 11 при одном.

# Почему это записано как инвариант

Документация обещала «минимум 50 за запрос, сверху зависит от строк и полей», и
по ней была построена модель «50 за запрос». Замер показал занижение **в девять
раз**: один запрос за 100 units дал больше, чем весь разбор документации.
Правило на будущее: цену внешнего API замеряют, а не читают.

# Следствия, на которых стоит вся экономия

| Следствие | Число |
|---|---|
| Минимум делает дробление бессмысленным | три запроса по строке — 150, один на 13 строк — 143 |
| Минимум — это ещё и **неиспользованная ёмкость** | при цене строки 11 под 50 units влезает 4 строки (44), пятая пробивает (55) |
| Второе поле удваивает цену строки | 21 против 11 — поэтому шаг 1 просит только `org_traffic` |
| Цена строки зависит от endpoint'а | `keywords-history` — 51 (пять полей), `refdomains-history` — 5 |
| **Состав полей — рычаг, а не деталь** | та же ручка с двумя полями вместо пяти стоит 21 за строку: кривая позиций для кейса берёт `top3` и `top4_10`, остальные корзины остаются числами на границах |
| Кэш Ahrefs скидки не даёт | повтор при `x-api-cache: hit` стоит столько же; экономит только наш кэш закрытых месяцев |

# Чего замер не покрыл

Цена `keywords-history` и `refdomains-history` **не замерена** — расчёт для них
ведётся по той же формуле, что подтвердилась на `metrics-history`. Проверяется
первым живым ключом (см. [../../ops/first-live-run.md](../../ops/first-live-run.md)).
