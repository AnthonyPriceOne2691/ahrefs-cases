# Формула

```
стоимость запроса = max(50, строки × (1 + сумма цен полей))
```

| Поле | Цена |
|---|---|
| `org_traffic`, `org_cost`, `total_search_volume` | 10 |
| `refdomains` | 5 |
| `domain_rating`, `pages`, каждый ключевой бакет (`top3` … `top51_plus`) | 1 |
| `date` | 0 — это ось, а не метрика |

**Замерено живым ключом 12.09.2026** семью запросами узкими окнами; формула
сошлась на всех, включая крайние случаи: пять ключевых бакетов дают строку 6,
два дорогих поля — 21.

**Предыдущая редакция этого концепта («10 за любое поле») была неверна.** Она
выведена из единственного замеренного endpoint'а `metrics-history` 10.09.2026 и
перенесена на остальные по аналогии: там все поля дорогие, и ошибка не
проявлялась. На ключевых словах она завышала цену в семь раз, на ссылающихся
доменах — занижала.

# Почему это записано как инвариант

Документация обещала «минимум 50 за запрос, сверху зависит от строк и полей», и
по ней была построена модель «50 за запрос». Замер показал занижение **в девять
раз**: один запрос за 100 units дал больше, чем весь разбор документации.
Правило на будущее: цену внешнего API замеряют, а не читают.

# Следствия, на которых стоит вся экономия

| Следствие | Число |
|---|---|
| Минимум делает дробление бессмысленным | три запроса по строке — 150, один на 13 строк — 143 |
| Минимум — это ещё и **неиспользованная ёмкость** | при цене строки 11 под 50 units влезает 4 строки (44), пятая пробивает (55) |
| Второе **дорогое** поле удваивает цену строки | 21 против 11 — поэтому шаг 1 просит только `org_traffic` |
| Цена строки зависит от того, **какие** поля просим | `keywords-history` — 6 (пять дешёвых бакетов), `metrics-history` — 11 (одно дорогое поле) |
| **Дорог только трафик** | позиции, DR и страницы стоят по единице за поле: отказываться от них ради экономии смысла нет — вся история DR за период стоит 50 units, то есть один минимум |
| Состав полей остался рычагом, но слабым | кривая позиций с двумя бакетами вместо пяти — 3 против 6 за строку; на 18 месяцах это 50 против 108, и чаще всё упирается в минимум запроса |
| Кэш Ahrefs скидки не даёт | повтор при `x-api-cache: hit` стоит столько же; экономит только наш кэш закрытых месяцев |

# Чего замер не покрыл

**Тарифицируется ли это вообще.** Все ответы 12.09.2026 пришли с
`x-api-units-cost-total-actual: 0`, и счётчик `units_usage_api_key` не сдвинулся
ни на один unit за девять запросов. Два независимых признака говорят «списано
ноль», но отличить «эти запросы не тарифицируются» от «счётчик обновляется раз в
сутки» одним днём нельзя. До проверки повтором сервис считает по смете и ничего
в поведении не меняет: ошибка в сторону «бесплатно» стоила бы квоты заказчика.
