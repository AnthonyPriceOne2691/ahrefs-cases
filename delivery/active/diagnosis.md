# Diagnosis journal

**Симптом:** в PDF по `wickes.co.uk` таблица «А → Б» показывает 35 394 → 60 101,
а кривая органического трафика заканчивается на 1 058 129 — разница в
семнадцать раз на одном листе.
**Repro:** на стенде есть и живые, и фикстурные ряды одного проекта (норма:
фикстуры пишутся разработкой, живые приехали калибровочным прогоном);
`classify` был выполнен по одному источнику, `cases`/`render` — по другому.

- H1: график рисуется по другой метрике → ОПРОВЕРГНУТА: подпись и ряд те же
  (`org_traffic`), различаются только величины
- H2: точка Б — среднее по окну, отсюда расхождение с последним месяцем
  (L46) → ОПРОВЕРГНУТА: L46 объясняет разницу в проценты, а не в семнадцать раз
- H3: таблица и кривая читают разные источники → ПОДТВЕРЖДЕНА: числа таблицы
  совпадают с фикстурными точками, числа кривой — с живыми

**Корневая причина:** у вердикта нет источника. `build_cases(source=…)`
применяет источник только к сериям для кривых; таблица и текст приходят из
записанного вердикта, который посчитан неизвестно по чему. Два потребителя
одних данных — один помнит, откуда они, второй нет, и сверить их не с чем.

**Почему прошло мимо гейтов:** тесты идут в одном источнике (`fixture`), и в
нём совпадение источников выполняется само собой — как в L107, где умолчание
`source=FIXTURE` было невидимо ровно потому, что тесты и сами шли в этом
режиме. Чтобы дефект проявился, в базе должны лежать ряды **двух** источников
по одному проекту: на стенде это нормальное состояние, в тестах — никогда.
