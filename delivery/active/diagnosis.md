# Diagnosis: гейт мержа блокирует мерж дефектом своего окружения

## Симптом

24.09.2026, `DRY_RUN=1 bash scripts/merge_guard.sh <ветка> main` из клона с
чистым деревом: красный `pre-commit (all files)` с текстом
`Oops! Something went wrong! :( ESLint: 10.11.0`. В проекте
`web/node_modules/eslint` — 9.39.5. Обход — переменная
`MERGE_GUARD_BORROW="web/node_modules .venv node_modules"` на каждом вызове.

| Гипотеза | Вердикт | Чем проверена |
|---|---|---|
| ① Код ветки нарушает eslint | **ОПРОВЕРГНУТА** | ветка равна `origin/main`, в клоне `pre-commit run --all-files` зелёный; ESLint 10 падает на загрузке конфига (`Cannot find package '@eslint/js' imported from …/web/eslint.config.js`) — до чтения кода |
| ② ESLint 10.11.0 — глобальная установка | **ОПРОВЕРГНУТА** | `which eslint` — пусто; в `npm root -g` только `corepack` и `npm` |
| ③ npx берёт eslint из своего кэша | **ПОДТВЕРЖДЕНА** | `~/.npm/_npx/515228b7c8d004a2/package.json`: `"eslint": "^10.11.0"`, `_npx.packages: ["eslint"]` — след давнего `npx eslint` вне проекта. `--no-install` запрещает установку, но не кэш |
| ④ Во временном дереве нет `web/node_modules` | **ПОДТВЕРЖДЕНА** | вывод merge_guard — одна строка «одолжено окружение: .venv»; умолчание `BORROW_DIRS` = `backend/.venv frontend/node_modules .venv node_modules`, дословно из CQG §8.5.2 под раскладку `frontend/` |
| ⑤ Ломается только eslint | **ОПРОВЕРГНУТА** | pre-commit без `web/node_modules`: красных хука два — eslint и prettier (`npx canceled due to missing packages and no YES option: ["prettier@3.9.9"]`). Prettier не был виден: merge_guard печатает первые 15 строк вывода гейта |
| ⑥ Остальные гейты фронта в том дереве судили | **ОПРОВЕРГНУТА** | без `web/node_modules` четыре гейта выходят 0, не просудив TS: eslint-ратчет («eslint не найден — warning-ратчет пропущен»), jscpd («jscpd не найден — DRY-гейт пропущен»), слои и сложность (половина ts «НЕ проверена») |

## Механизм

`git worktree add` приносит только отслеживаемые файлы, поэтому гейт мержа
одалживает окружение симлинками из клона (канон `cqg@1.26`). Список каталогов
канон объявил настраиваемым, а умолчание дал под свою раскладку. Проект при
развёртывании переписал раскладку `frontend/` → `web/` во всех хуках
`.pre-commit-config.yaml` (`LINT_FE_DIR=web`, `files: ^web/src/`, `cd web`), но
не в `BORROW_DIRS` — там раскладка сидит в умолчании, а не в настройке, и отказ
проявляется только на мерже.

Во временном дереве без `web/node_modules` npx не находит локального eslint и
идёт в свой кэш: какая версия там окажется, решает история машины, а не проект.
Здесь нашлась 10.11.0, и она падает на конфиге проекта, потому что его импорты
(`@eslint/js`, `typescript-eslint`) разрешаются только из `web/node_modules`.

## Почему не видели раньше

Приёмка контура 10.09.2026 записала «merge_guard: да» — наличие, а не прогон:
в архиве поставок нет ни одного вывода гейта мержа (поиск «одолжено окружение»
и «DRY_RUN» по `delivery/` — 0 совпадений). Поставки сливались через PR, и
умолчание списка ни разу не проверялось на раскладке проекта.
