# Diagnosis journal

**Симптом:** в аннотациях каждого прогона `quality` висит
`editable-установка backend не удалась — mypy может не видеть рантайм-зависимости проекта`.
Прогон при этом зелёный.
**Repro:** любой push в main; `gh run view <id>` показывает аннотацию.

- H1: установка правда падает и mypy работает вслепую → проверил: шагом выше
  стоит `.venv/bin/pip install -e '.[dev]'` (ветка «манифеста нет»), то есть
  проект в venv уже установлен, и mypy видит и `pydantic`, и остальное →
  ОПРОВЕРГНУТА
- H2: сломан сам `pip install -e backend` → проверил: `ls backend` — каталога
  нет; ставить нечего, pip отвечает отказом законно → ПОДТВЕРЖДЕНА

**Корневая причина:** шаг взят из шаблона контура и предполагает раскладку
`backend/` + `frontend/`. В этом проекте питоновский пакет лежит в корне
(`src/`-layout), и условие `[ -f pyproject.toml ]` — корневой файл — запускает
установку **каталога, которого нет**. Условие проверяет одно, а команда делает
другое.

**Почему прошло мимо гейтов:** гейты смотрят на код, а не на аннотации CI;
предупреждение по построению не делает прогон красным. Единственный оракул
здесь — человек, читающий аннотации, и ровно его это предупреждение и изнашивало.
Класс тот же, что у L73: зелёный прогон, доказывающий меньше, чем кажется.
