# Diagnosis journal

**Симптом:** на тёмной теме веб-карточки подписи значений кривой (`169 720`,
`888`) сливаются с фоном, а нижняя часть заливки выглядит белой дымкой поверх
тёмного полотна.

**Repro:** `tests/test_cases_charts.py::test_chart_carries_its_own_paper`
(структурно) плюс осмотр карточки в тёмной теме.

- H1: тема не доходит до карточки, и виноват стиль страницы → проверил:
  остальная карточка (текст, таблицы, плашки) в тёмной теме читается, страдает
  только область SVG → ОПРОВЕРГНУТА
- H2: рисунок не несёт собственного фона и рассчитан на белый лист →
  проверил `export/charts.py`: `INK = #0b0b0b`, градиент затухает в
  `SURFACE = #fcfcfb`, но ни одного элемента с этим цветом в разметке нет —
  «полотно» подразумевается листом PDF → ПОДТВЕРЖДЕНА

**Корневая причина:** артефакт, общий для печати и экрана, опирался на **фон,
которого не содержит**. Пока потребитель был один (лист PDF), подразумеваемое
полотно совпадало с настоящим. Второй потребитель (веб-карточка с темой) принёс
другое полотно, и рисунок оказался нарисован для чужого.

**Почему прошло мимо гейтов:** ни один оракул не смотрит на контраст, а тесты
рисунка проверяют структуру (есть кривая, есть полосы окон, есть подписи).
Увидеть можно только глазами и только на тёмной теме — то есть при условии,
которое в CI не воспроизводится. Кандидат на правило: артефакт, показываемый в
нескольких средах, обязан нести свою подложку, а не полагаться на чужую.
