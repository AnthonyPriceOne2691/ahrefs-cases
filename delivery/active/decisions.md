- 2026-09-28 · выбрал `uv.lock` с установкой pip из `uv export --locked` вместо `requirements*.txt` от pip-compile — потому что предохранитель поставки и гейт новых зависимостей знают `uv.lock` как сгенерированный файл, а `requirements.txt` с хешами (тысячи строк) считали бы кодом; `--locked` сам роняет сборку на устаревшем lock; установщик в образе и CI остаётся прежний, pip
- 2026-09-28 · выбрал первый lock на момент последнего зелёного CI (`--exclude-newer 2026-09-25T16:34:00Z`, затем пересборка без флага — версии те же, опция из lock ушла) вместо «последнего на сегодня» — потому что поставка про фиксацию, а не про подъём: набор, повторяющий прод и зелёный CI, не может уронить ни то, ни другое
- 2026-09-28 · выбрал `[tool.uv] environments` = Linux и macOS вместо универсального lock на все платформы — потому что код идёт только там (прод и CI — Linux, разработка — macOS), а колёса Windows раздували lock до 574 КБ при пороге хука крупных файлов 512 КБ (стало 474 КиБ)
- 2026-09-28 · выбрал точную версию uv (`required-version = "==0.12.19"`, та же в Dockerfile и CI) вместо диапазона — потому что lock, записанный более новой версией, закреплённая в CI может счесть устаревшим, и `--locked` уронит сборку без правки зависимостей; скрипт пересборки берёт нужную версию через `uvx` сам
- 2026-09-28 · выбрал uv в образе монтированием из официального образа на время одной команды (`RUN --mount=from=uv`) вместо копии в образ — потому что uv нужен только перевести lock в список для pip; в боевом образе его нет
- 2026-09-28 · выбрал исключить `uv.lock` из `check-added-large-files` вместо ожидания, когда он перерастёт 512 КБ — потому что это сгенерированный файл, который сверяет `--locked`, а хук стоит против случайных двоичных файлов; запас до порога — 38 КиБ, первый же новый пакет с колёсами его съест
