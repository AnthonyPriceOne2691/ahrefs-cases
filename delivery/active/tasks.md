# Tasks: last-keyholder-keeps-the-key

## Mini-spec

**Проблема.** Единственный управляющий (на проде — anthony@, группа engineer)
снял с себя «добавлять пользователей» личным «Нет» — и вернуть право стало
некому: экран людей отвечает 403, а других управляющих нет. Защита
«последний администратор» считает только группу admin, личные права не
проверяются вовсе, а смена своей группы у инженера не проверяется тоже.

**Правило (выбор владельца — строгое).** Лишить себя права «добавлять
пользователей» нельзя никаким путём — ни личным «Нет», ни сменой своей группы,
**даже если есть другие управляющие**. Это делает только другой управляющий.
Так же, как нельзя выключить и удалить себя.

Следствие: API отвечает только тому, у кого право есть, и себя этот человек
его не лишит, не выключит и не удалит — значит, управляющий в сервисе
остаётся всегда, и отдельный подсчёт «последнего» не нужен.

**Примеры приёмки.**

- **U1.** Управляющий ставит себе личное `manage_users: false` → 409, текст
  называет, кто может это сделать («другой управляющий»); право на месте.
- **U2.** Управляющий переводит себя в группу `user` при живом втором
  администраторе → 409 тем же текстом (прежняя защита «последний
  администратор» здесь не срабатывает — проверяется новая).
- **U3.** Управляющий снимает `manage_users` с другого → 200 (страж от
  перегиба: правило про себя, а не про право).
- **U4.** Управляющий переводит себя из admin в engineer (право остаётся) → 200
  (страж от перегиба: запрещено терять право, а не менять группу).
- **U5.** Прежние отказы не меняются: себя не выключить, не удалить, последний
  администратор — существующие тесты зелёные.

**Вне рамок.** Текст 403 «нет права manage_users: группа engineer» называет
ключ, а не работу, и группу вместо личного запрета; с правилом до этого экрана
управляющий не дойдёт. Отмечено в verify-report.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L60** — перенося защиту, переноси причину. Новое правило пишется в
  докстринг роутера рядом с «себя не выключить»: без причины строгое «себе
  нельзя, даже если есть другие» выглядит перестраховкой и уйдёт при первом
  рефакторинге.
- **L59** — роль отвечает «кто он», доступ — «что ему можно». Дыра ровно
  здесь: защита смотрела на роль (`group == ADMIN`), а доступ теряется и личным
  «Нет». Итог «после правки» считается той же `rights_of_user`, что решает
  доступ, а не второй копией правила перекрытия.
- **L160** — правило «последнего администратора» нельзя проверять его же
  руками, тест зеленеет по неверной причине. Для U2 это значит: живой второй
  администратор обязателен, иначе смену группы отобьёт прежняя защита, и тест
  будет зелёным без новой. Утверждение — по тексту отказа, а не только по 409.
- **L68** — инвариант на всю базу тест через API не изолирует. Строгое правило
  от всей базы не зависит (про себя — всегда), поэтому подопытному не нужно
  быть «последним», и чужие управляющие дев-базы тесту не мешают.
