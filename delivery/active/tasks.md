# Tasks: структура кейса

Уроки архива, применимые к диффу: L40, L32/L34, L30, L23, L13, L8, L33 — см. plan.md.

## Модель
- [ ] `CaseData` с блоками ТЗ: гео, период, задача, что сделали, А → Б
- [ ] `Change`: было, стало, абсолют, процент (или его отсутствие)
- [ ] `CaseOutcome`: четыре исхода, а не «собрался / не собрался»
- [ ] подписи метрик по-русски в одном месте

## Сборка
- [ ] точки А и Б читаются из записанного вердикта, строго по форме
- [ ] анонимность решается один раз: заголовок «сайт в нише X»
- [ ] `work_volume` пуст → блока «что сделали» нет
- [ ] «число ключей» — сумма пяти корзин и только при всех пяти
- [ ] сигнал «куплено, но не в вердикте» вместо молчания
- [ ] версия порогов из вердикта, а не из активного набора

## CLI
- [ ] команда `cases [--domain X] [--version V]`, печать по четырём исходам
- [ ] считает проекты, а не строки (L13)

## Канон
- [ ] концепт «Из чего состоит кейс» с инвариантами

## Проверки
- [ ] E1–E10
- [ ] тест чистит за собой (L8)
- [ ] сквозной прогон на фикстурах: intake → collect → stage2 → classify → case-data → cases
