# Tasks: run-keeps-its-pack

## Mini-spec

**Проблема.** Владелец просит забирать кейсы кнопкой на прогоне (25.09.2026). Сейчас это невозможно
в принципе: пачка одна — каждая сборка переписывает архив дня, «свежей» считается последняя по времени
файла, а кейс и файл не помнят, какой прогон их собрал. Первая поставка из двух — сервер: у каждой
сборки своя копия архива и выдача по номеру прогона. Кнопки в журнале — следующая поставка
(`run-row-case-buttons`).

**Примеры приёмки.**

- **P1.** Сборка кейсов откладывает копию своей пачки (`runs/<номер>/…-прогон-<номер>.zip`), строка
  журнала — `pack: true`, `GET /api/runs/<номер>/pack` отдаёт её; PDF внутри — те же, что в свежей пачке.
- **P2.** Сборка, не собравшая архива, копии не оставляет: свежий архив каталога — прежний и чужой ей
  (`pack: false`, выдача — 404 со словами).
- **P3.** Вторая сборка того же дня переписывает пачку дня, но не копию первой: у каждой своя.
- **P4.** Копия с кейсом удалённого проекта не отдаётся — 409 со словами (правило владельца 24.09 для пачки).
- **P5.** `build_cases` — только у последнего готового прогона «данные под кейс», после которого сборки не
  было; у остальных `false`.
- **P6.** Прогон без копии (шаг 1) — 404 со словами; путь в снимке вне `runs/` не отдаётся.
- **P7.** Без токена — 401.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L89** — «свежая» пачка — по времени файла, а не по имени: сборка того же дня переписывает архив того же
  имени. Отсюда и отпечаток «до сборки» — путь **и** время: одного имени мало (P3).
- **L130** — «записано» и «видно человеку» — разные стадии: копия и флаг — эта поставка, кнопка — следующая.
- **L217** — ключ сопоставления задаёт вызываемый: копия ищется по номеру прогона, а не по имени архива.
