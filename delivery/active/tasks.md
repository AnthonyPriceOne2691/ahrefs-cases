# Tasks: hotfix — реапер добивает живой прогон (Z1)

Мини-спека класса S. Дефект и разбор гипотез — `diagnosis.md`.

**Ожидаемое поведение.** Утверждение «живой прогон не идёт дольше своего
лимита» должно стать правдой, а не предположением; порог реапера — считаться
от этого лимита, а не подбираться отдельно.

## Лимит прогона
- [x] `COLLECT_RUN_TIMEOUT_SEC` в конфиг (дефолт 4 часа) + `.env.example`
- [x] прогон получает дедлайн от старта; задачи после дедлайна не выполняются
- [x] оставшиеся задачи помечаются `skipped_aborted` с причиной «превышен лимит времени»
- [x] статус такого прогона — `partial`, а не `done`: часть работы не сделана

## Согласованность с реапером
- [x] дефолт `COLLECT_RUN_STALE_SEC` поднят выше лимита прогона (4,5 часа)
- [x] инвариант в конфиге: порог реапера **строго больше** лимита прогона, иначе отказ на старте
- [x] текст ошибки называет оба числа и объясняет, чем это грозит

## Проверки
- [x] repro-тест: несогласованные числа не дают собрать конфиг (защита от возврата)
- [x] тест: прогон, упёршийся в дедлайн, закрывается `partial`, остаток не запрашивается
- [x] тест: обычный прогон дедлайном не задет
- [x] `docs/FINDINGS.md`: строка Z1 переезжает из «заведомо не заработает» в исправленные
