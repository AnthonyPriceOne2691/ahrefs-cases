# Tasks: niche-digits-in-text

## Mini-spec

**Проблема.** Ниша из входного файла с цифрой — «3D-печать», «B2B», «Web3» — роняет сборку текста кейса:
`verify_numbers` читает её цифру как число кейса и бросает `NumbersMismatchError`. Ни `build_cases`, ни задача
пачки это исключение не ловят (изолирован только контент-запрет), поэтому один такой проект роняет пачку
целиком — всем проектам файла. Найдено разведкой этапа «PDF-бриф» 07.10.2026; с нишей «Тематика · Тип сайта»
(этап 2) такие ниши станут чаще.

**Решение.** Ниша вырезается из текста перед сверкой — как названия метрик («топ-10», урок L47), и только
**в кавычках**, в которых её ставит `_intro`: совпавшее с ней число в остальном тексте сверяется по-прежнему.

**Примеры приёмки.**
- **I1.** Ниши «3D-печать», «B2B», «Web3 · агрегатор 24/7» — текст собирается и называет нишу в кавычках.
- **I2.** Ниша «3D-печать», а в тексте вне кавычек «за 3 квартала» — сверка по-прежнему бросает
  `NumbersMismatchError`.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L47** — ровно этот класс: цифра — часть имени; лечится исключением имени из сверки, а не добавлением
  цифры в допустимые числа (это ослабило бы сверку по всему тексту).
- **L48** — тест проверяет содержание (ниша в кавычках в тексте), а не место предложения.
- **L127** — правило сверки живёт в `narrative.verify_numbers`, через который проходят все пути сборки текста.

- **L57**, **L138**, **L142**, **L235** — не применимы: статусов ответа, выбора источника рядов, команд CLI и
  журнала поставка не трогает.
