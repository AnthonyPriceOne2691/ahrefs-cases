# Tasks: alerts-runs-and-health

## Mini-spec

**Проблема.** Push-алертов нет: `/api/alerts` отвечает состоянием экрану, и об упавшем прогоне узнают,
только открыв журнал; лежащий сервис не скажет о себе никому. Бэкап кричит с поставки
`offsite-backup-copy`; владелец поручил алерт в Telegram и при падении прогона, и при провале
healthcheck (ревью 28.09.2026).

**Решение.** (1) Реапер раз в тик объявляет упавшие прогоны: берёт `failed` после отметки «объявлено до»
(время закрытия и номер — в Redis), шлёт в Telegram по одному с номером, ступенью и причиной, двигает
отметку за каждым доставленным. Первый запуск историю не объявляет; отказ Telegram — повтор в следующий
тик. Отправка — `workers/telegram.py` (httpx), в журнал идут только тип ошибки и код ответа: в адресе
запроса токен бота. Настройка — `config.alerts` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — та же пара,
что у скриптов хоста). (2) `scripts/healthcheck.sh` из крона раз в пять минут: контейнеры запущены и не
unhealthy, API отвечает `ok` через web, ночной бэкап моложе 26 ч, внешняя копия — тоже, если настроена.
Алерт — на смене состояния («беда …» / «снова в порядке»), не на каждом тике.

**Примеры приёмки.**
- **X1.** Отметки нет (первый запуск) — ставится на «сейчас», история не объявляется.
- **X2.** Упавшие после отметки — по одному сообщению по порядку, с номером, ступенью и причиной (пустая —
  «причина не записана»); удачные не объявляются; повтора нет.
- **X3.** Telegram не принял — отметка стоит, следующий тик пробует тот же прогон.
- **X4.** Два прогона с одним временем закрытия — оба доходят.
- **X5.** Отправка — POST `sendMessage` с чатом и текстом; длинный текст режется до 4000.
- **X6.** Ошибка сети и отказ Telegram — False и строка в журнале без токена.
- **X7.** Канал не настроен — ни одного запроса; наполовину — назван недостающий.
- **X8.** Сторож: всё в порядке — тишина; беда — один алерт; та же беда — тишина; прошла — «снова в порядке».
- **X9.** Сторож: бэкап старше 26 ч — беда.

**Вне рамок.** Учётка бота (создаёт владелец); алерт о расходе units (экран `/api/alerts` его показывает,
push — отдельное решение); внешний сторож «машина целиком недоступна» (изнутри машины не виден —
рекомендация владельцу в отчёте).

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L146** — граница с внешней системой: таймаут 20 с и потолок текста у отправки; Telegram лёг — реапер
  не ждёт и не падает, отметка стоит.
- **L125** — ошибка при обработке ошибки: сбой Redis в объявлении ловится и пишется отдельно, проход
  реапера и его отметка о жизни не страдают.
- **L24** — паттерн переносится с опорой: отметка держится на времени закрытия, которое ставят все пути
  `failed` (`finished_at`), с запасом `created_at`.
- **L4** — конфиг алертов читается алиасами переменных; тесты подменяют поля готового `config.alerts`, а
  не конструируют `Settings(...)`.
- **L5** — миграций поставка не заводит: `migrations/env.py` меняет только настройку журнала (`disable_existing_loggers=False`), цикл upgrade → downgrade тот же.
- **L57**, **L64** — путь отказа проверен тестом: Telegram лёг или отказал (X6), Redis без ответа — строка в журнале, а не исключение прохода; `httpx.codes.OK`, а не имя статуса, которое устареет.
- **L221** — не применим: про вид домена на экранах; `api/routers/alerts.py` меняет только докстринг (кто доставляет алерты).
- **L3** — вариант D: скрипт и тесты — механика, коммитятся; `extract_payload.py --check-local` — два нуля.
- **L55**, **L86**, **L230** — не задеты: реапер — свой процесс со своим циклом, сессия — из того же
  `get_sessionmaker`, что у прохода.
