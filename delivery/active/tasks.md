# Tasks: python-lock-file

## Mini-spec

**Проблема.** Зависимости Python заданы только нижней границей (`pyproject.toml`), lock-файла нет: CI и
сборка образа ставят то, что вышло в день сборки. 24.09.2026 это уже уронило CI у всех — SQLAlchemy 2.1.0
вышел между двумя прогонами одной ветки (47 падений, L223, `2b25a99`); прод уцелел, потому что был
собран часом раньше. Граница `<2.1` закрыла один пакет, остальные по-прежнему плавают (Z48). Ревью
28.09.2026 назвало это же, и владелец поручил: образ и CI ставят зависимости из lock-файла, CI зелёный.

**Решение.** Источник правды — `uv.lock` (универсальный, с хешами, для Linux и macOS). Ставит его
тот же pip, что и раньше: `uv export --locked` переводит lock в список с хешами и падает, если
`pyproject.toml` правили без пересборки lock, затем `pip install --require-hashes`, проект — `--no-deps`.
Так в образе и CI (джобы `tests` и `gates`). Первый lock — не «последнее на сегодня», а заведомо рабочий
набор: версии на момент последнего зелёного CI (`--exclude-newer 2026-09-25T16:34Z`), и он сверен с
прод-контейнером. Пересборка — `scripts/lock_deps.sh`; версия uv одна у скрипта, образа и CI
(`[tool.uv] required-version`). Инструменты, которые CI ставил мимо манифеста (`detect-secrets`,
`types-PyYAML`), переехали в `dev`-extras; `pytest-env` не нужен (ключа `env` в настройках pytest нет).

**Примеры приёмки.**
- **K1.** Каждая прямая зависимость `pyproject.toml` (рантайм и `dev`) есть в `uv.lock`, и записанная
  версия удовлетворяет границе манифеста (SQLAlchemy `<2.1` — 2.0.54).
- **K2.** Образ, стадии `dev` и `prod`: зависимости — `uv export --locked` и `pip install --require-hashes`,
  проект — `--no-deps`; ни одного `pip install` мимо lock.
- **K3.** CI, джобы `tests` и `gates`: установка из lock тем же способом, `pip check` после; pre-commit —
  из venv, а не `pip install pre-commit` мимо манифеста.
- **K4.** Версия uv одна: `[tool.uv] required-version`, образ uv в `Dockerfile`, `setup-uv` в обеих джобах.
- **K5.** Lock повторяет проверенный набор: рантайм — `pip freeze` контейнера api прода, dev — список
  установленного зелёного CI 25.09 (run 36161575384).
- **K6.** Образ `prod` собран из lock: `pip freeze` совпадает с продом, `pip check` чист, внутри
  рендерится PDF и импортируется приложение.
- **K7.** CI на PR зелёный, в логе установки — версии из lock.

**Вне рамок.** Переход на `postgresql.distinct_on` вместе с SQLAlchemy 2.1 (граница `<2.1` остаётся —
Z48 по второй половине); подъём версий (первый lock намеренно повторяет рабочий набор); `pip install
PyYAML` в джобе `delivery` — инструмент selftest канона, ветвь которого в варианте D не исполняется.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L223** — корень поставки: версия без lock — решение, отданное чужому релизу. Лечится записанными
  версиями, а не новой границей.
- **L6** — venv гейтов обязан содержать сам проект, иначе mypy и pip-audit смотрят не туда: проект
  ставится в тот же `.venv` (`--no-deps -e .`), список для pip-audit — из того же lock.
- **L69**, **L84** — образ проверяется сборкой и исполнением («образ делает продукт»), а не чтением
  Dockerfile: K6.
- **L44** — системная библиотека HarfBuzz в CI остаётся шагом ОС; lock её не заменяет.
- **L100** — ветка «нет манифеста» в шаге установки не должна печатать предупреждение там, где lock есть:
  lock проверяется первой веткой и печатает свой выбор.
- **L163** — зелёное без судимого не считается: `pip check` и `--locked` падают на устаревшем lock,
  K1 падает на манифесте без lock.
- **L7**, **L16**, **L36**, **L207** — адаптации канонного workflow объявляются в
  `scripts/lint/adapted.json`, а не молча.
- **L3** — вариант D: `uv.lock` и `scripts/lock_deps.sh` — механика, они коммитятся; `extract_payload.py
  --check-local` — два нуля до каждого коммита.
- **L57** — тот же класс, что L223: `filterwarnings = error` ловит чужое устаревание; lock не даёт ему
  прийти незваным — новые версии приходят только поставкой подъёма, где CI покажет предупреждения.
- **L138**, **L142** — не применимы: про источник данных команд CLI и живой режим, а поставка трогает
  только установку зависимостей (`docs/FINDINGS.md` — строкой Z48).
- **L35**, **L166**, **L167** — не задеты: гейт синхронности канона, покрытие подпроцессов и срок
  отсрочки покрытия (истекает 29.09.2026, Z22) эта поставка не меняет.
