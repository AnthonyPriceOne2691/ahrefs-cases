# Plan

Класс M. Вычесть из ответа API то, чего его счётчик ещё не видел, и снять
умолчания у предохранительных аргументов.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L53** — предохранитель, которому можно не передать аргумент, не сработает:
  умолчание `reserved=0` того же класса, что умолчание источника рядов.
- **L110** — у внешнего лимита бывает второй источник правды; потолок собирается
  из всех, а не из самого удобного. Здесь второй источник — наш журнал.
- **L112** — величина отвечает на вопрос про изменение, только если сама
  является изменением: остаток из API — это «на вчера», а не «сейчас».
- **L23** — молчаливый ответ хуже отказа: завышенный остаток выглядит как
  «хватает» и кончается отказом на середине прогона.

Не применимы: **L88** (файлов не добавляем), **L113** (режимов у одной команды
не появляется).

## Шаги

1. `config/ahrefs.py` — `units_counter_lag_hours` (24), с замером в докстроке.
2. `collect/budget.py` — `live_spend_since` и `uncounted_spend`.
3. `collect/quota.py` — `preflight` без умолчаний, вычет в `available`, причина
   отказа называет все четыре числа.
4. `collect/runner.py`, `api/routers/runs.py` — считают вычет и передают.
5. `api/routers/usage.py` + `schemas.UsageView` — тот же остаток на экране,
   отдельным числом «сколько вычли».
6. `web/src/pages/UsagePage.tsx` — строка про вычет, когда он ненулевой.
7. `scripts/probe_next_day.py` — зовёт `live_spend_since` вместо своего запроса.
8. Тесты: E1–E5 плюс оракул на сигнатуру.

## Rejected alternatives

- **Не снимать резерв после прогона** (держать его сутки) — отклонено, потому что резерв
  перестал бы означать «идущий прогон», и два смысла в одном поле разошлись бы
  на первом же упавшем прогоне. Комментарий в `reserved_units` прямо запрещает
  компенсирующие записи — это тот же случай.
- **Считать остаток только по своему журналу**, игнорируя Ahrefs, — отклонено, потому что
  воркспейс расходуют соседние сервисы агентства (за сутки 362 833 units), и
  наш журнал о них ничего не знает.
- **Уменьшить `current_month_ttl_hours` / ждать обновления счётчика** —
  отклонено, потому что это ожидание в часы ради числа, которое у нас уже есть в базе.
