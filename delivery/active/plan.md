# Plan

Класс M. Перевести инвариант «активная версия одна» из дисциплины в ограничение
базы и починить тех, кто на дисциплину опирался.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L79** — дев-база общая и живёт между прогонами: уборка обязана быть точной.
- **L127** — правило, стоящее в вызывающем, действует только на него.
- **L8** — не оставляй базу без активных порогов следующему модулю.

Не применимы: **L131**, **L132** — имён доменов поставка не трогает.

## Шаги

1. Миграция: погасить лишние активные, создать частичный уникальный индекс.
2. Модель: тот же индекс в `__table_args__` — чтобы схема из метаданных
   совпадала с миграцией.
3. `recalc.activate`: погасить все одним `UPDATE`, затем зажечь одну.
4. `tests/owned_rows.py`: `active_versions`, `make_active`, `restore_active`.
5. Три теста с базой: запоминают действующую версию, делают своей, возвращают.
6. Оракул: две активные версии невозможны (savepoint, иначе падение утащит
   внешнюю транзакцию).

## Rejected alternatives

- **Отложенное ограничение (`DEFERRABLE`)** — отклонено, потому что Postgres не
  поддерживает отложенность у частичных уникальных **индексов**, а уникального
  частичного *ограничения* в нём нет вовсе: пришлось бы городить триггер.
- **Оставить инвариант дисциплиной и просто починить тесты** — отклонено,
  потому что дисциплина уже дала сбой дважды (в тестах и на стенде), а цена
  сбоя — вердикты по неутверждённым порогам.
- **Хранить активную версию отдельной таблицей-указателем** — отклонено,
  потому что это вторая правда о том же: указатель и флаг разошлись бы, и
  вопрос «какая версия действует» получил бы два ответа.
