# Plan: screenshots-screen

## Шаги

1. `api/routers/screenshots.py` — `GET /api/screenshot-rules`: виды словами (`KIND_LABELS`), предел тела,
   предел числа на проект, длинная сторона ужатия.
2. `web/src/api/screenshots.ts` + типы — правила, список, загрузка сырым телом, картинка `data:`-адресом,
   удаление; форма ответа проверяется при получении.
3. `web/src/pages/card/shrink.ts` — ужатие больше предела до отправки по числам сервера.
4. `web/src/pages/card/Screens.tsx` — блок за пунктами брифа (`Brief.tsx`): миниатюры, загрузка,
   удаление с подтверждением; без права — только смотреть.
5. `web/src/pages/card/DeleteProject.tsx` — окно удаления и итог называют скрины.
6. Знания: `product/brief.md` (п. 14).

- **L57**, **L64** — новых статусов отказа поставка не вводит.
- **L240** — в докстроках тестов номеров уроков нет.

## Rejected alternatives

- **Миниатюра `blob:`-адресом** — отвергнуто, потому что политика безопасности прода (`img-src 'self'
  data:`) его не пускает: проверено на продакшен-сборке с заголовком из `deploy/nginx.conf`.
- **`<img src="/api/screenshots/{id}/image">`** — отвергнуто, потому что браузер отправит его без
  заголовка `Authorization` (токен не в куке) и получит `401`.
- **Отправить большой и ждать `413`** — отвергнуто, потому что через прокси ответ сервера до человека не
  доходит (урок экрана приёма списка): ужимаем и отказываем до отправки.
- **Виды скринов в каталоге брифа (`/api/brief-fields`)** — отвергнуто, потому что правила скринов —
  забота их роутера, и каталог брифа со старыми заглушками тестов остаётся прежней формы.
