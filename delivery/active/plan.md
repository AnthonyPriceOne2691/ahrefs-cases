# Plan: brief-known-more

Класс M: правило подстановки, факты кейса и карточки, загрузка параллельных проектов, экран карточки и тесты — больше
пяти файлов (§2.2b). Один исполнитель; код запроса к сайтам для следующей поставки пишет второй — в своём worktree, в
этой ветке его нет.

## Шаги

1. **Repro (M141, M142):** тесты словаря на нишах прода и строки пустого брифа — красные на `origin/main`.
2. `export/brief_known.py`: в `BriefFacts` — «вёл проект», месячный ряд органического трафика, Domain Rating точек А и
   Б, параллельные проекты домена (умолчаний нет, L74); правила `prepared_by`, `difficulties`, `parallel_services`,
   `features`; пороги просадки (15 %) и падения DR (3 пункта) — константами со строкой «умолчание агента», как
   `MONTHLY_FROM_MONTHS`; словарь ниш — по нишам прода (M137–M141).
3. Параллельные проекты домена — один запрос (`storage`), его зовут и сборка кейсов (`cases/builder.build_cases` →
   `CaseData.parallel`), и карточка (`api/routers/projects.py`); порядок — по началу периода и id (L218).
4. Лист берёт факты из `CaseData` (ряд трафика — `case.series`, DR — `case.change("dr")`), карточка — из своих рядов
   (`chart_series` того же источника) и таблицы А → Б вердикта; сличающий тест на всех новых пунктах (M143).
5. `web/src/pages/card/Brief.tsx`: пустой бриф — одна строка со счётом подставленного и оставшегося, кнопка
   «Показать подставленное» (M142, Z64).
6. Канон (`knowledge/product/brief.md` — инвариант 10: какие пункты подставляются), реестр (Z64), стенд: «Пересобрать
   кейсы», PDF растеризован; карточка в Chrome — пустой бриф, кнопка, список.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L258** — лист и карточка сличаются одним тестом: M143 на проекте, где срабатывают все новые правила.
- **L260** — число «сколько заполнено» считается той же функцией, что заполняет: счёт карточки — по `brief_known`, а не
  по каталогу.
- **L78** — правило, умеющее «не знать», одно: нет «вёл проект», нет просадок, нет пары — нет подстановки, а не
  догадка; экран значений не повторяет.
- **L74** — у новых полей `BriefFacts` умолчаний нет: лист и карточка называют каждое.
- **L41, L139** — трудности считаются по тому ряду, по которому собран кейс (тот же источник), а DR — по точкам А и Б
  вердикта, теми числами, что стоят в таблице листа.
- **L218** — параллельные проекты упорядочены по уникальному ключу (начало периода, id): порядок кучи Postgres не
  стабилен.
- **L221** — у каждой подстановки источник в скобках; трудности — «по динамике Ahrefs — уточните причину»: это
  подсказка, а не запись специалиста.
- **L240** — id примеров первыми в докстроках новых тестов.
- **L57, L64** — полный сьют под `filterwarnings = error`.
- **L243, L45** — лист брифа: длинная подстановка трудностей смотрится в PDF шрифтом прода, страницы «Динамики» не
  прибавляются.

## Rejected alternatives

- Трудности — по всем метрикам (ключи, ссылки, стоимость трафика) — отвергнуто: подсказка из пяти строк читается как
  отчёт, а не как вопрос специалисту; трафик — главная кривая кейса, DR — частый вопрос клиента.
- Просадку считать между любыми соседними точками ряда — отвергнуто: ряд хранит только измеренные месяцы, и пара через
  пропуск приписала бы одному месяцу падение за два.
- Параллельные услуги — по совпадению клиента, а не домена — отвергнуто: клиент в файле пишется свободно («ООО
  «Ромашка»»), домен — канон.
- «Кто подготовил» писать в бриф при сборке — отвергнуто (инвариант 10): подстановка считается при чтении; запись в
  бриф — только подпись сохранившего, как с 13.10.
- Пустой бриф развернуть списком подставленного без кнопки — отвергнуто: решение владельца 07.10 — одна строка, иначе
  цифры и «Почему эта группа» уезжают вниз.
