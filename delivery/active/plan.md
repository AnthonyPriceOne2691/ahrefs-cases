# Plan

Класс M. Один новый модуль — `classify/preview.py` — и общий проход, вынесенный
из пересчёта в `classify/verdicts.py`.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L30** (`classify/coverage.py`) — «не покупали» и «нет данных» разные
  состояния. В предпросмотре это значит: проект с нехваткой показывается
  отдельной строкой, а не среди «не изменится», иначе молчание читается как
  «всё в порядке».
- **L13** (`collect/run_journal.py`) — отчёт считает проекты. У предпросмотра
  легко посчитать «изменений 12» по парам групп вместо проектов.
- **L21** (`config/thresholds.default.yml`) — версии для тестов собираются в
  тесте, а не читаются из клиентских порогов.
- **L19** (`tests/test_classify_golden.py`) — версии в тестах отличаются
  настолько, чтобы группа менялась заведомо, а не по шуму на пороге.
- **L8** (`tests/conftest.py`) — «ничего не записал» проверяется счётом строк
  внутри транзакции теста, а не доверием к коду.

Не применимы: **L11**, **L24**, **L3** — сеть, прогоны и список игнора не
затрагиваются.

## Шаги

1. `classify/verdicts.py` — общий проход `evaluate`: расчёт плюс проверка
   покрытия по списку проектов, без записи.
2. `classify/recalc.py` — пересчёт встаёт на `evaluate` (цикл уезжает туда).
3. `classify/preview.py` — сравнение «было → стало», сводка, нехватка отдельно.
4. `scripts/run_collect.py` — подкоманда `preview <версия>`.
5. `tests/test_classify_preview.py` — E2, E3, E8, E8a, E9b.

## Rejected alternatives

- **Считать предпросмотр через временную запись и откат транзакции** —
  отклонено, потому что откат в проде означает открытую транзакцию на время
  ответа, а в тестах — что «ничего не записано» проверить нечем: строки
  появлялись бы и исчезали. Расчёт без записи проверяется счётом строк.
- **Показывать только сменивших группу** — отклонено, потому что проект без
  вердикта и проект с нехваткой данных не «не меняются», а не участвуют:
  молчание о них на калибровке читается как «всё в порядке» (урок L30).
- **Сортировать изменения по величине разницы** — отклонено, потому что
  порядок в CLI должен быть стабильным между запусками, иначе два вывода не
  сравнить глазами; сортировка для показа — вопрос экрана Ф6.
