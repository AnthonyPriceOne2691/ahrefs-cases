# Plan: brief-auto-list

Класс M: каталог пунктов брифа (сервер), правило подстановки (источник рядом с правилами), карточка, форма и тесты —
больше пяти файлов (§2.2b). Один исполнитель, основная копия.

## Шаги

1. **Repro (M145, M146):** тесты карточки и формы — красные на `origin/main` (пустой бриф — одна строка, форма без
   подписей).
2. `export/brief_known.py`: правило и источник — одной таблицей (`_RULES`: ключ → правило и откуда), `AUTOFILL` —
   ключ → откуда, вместе с подписью «Кто подготовил» (её пишет `api.routers.briefs._sign`). Второго списка нет.
3. `api/routers/briefs.py`: `BriefFieldView.autofill` из `AUTOFILL` (M144).
4. `web`: `BriefField.autofill`; `Brief.tsx` — пустой бриф: список «Сервис заполняет сам» со значениями проекта и
   серыми источниками, «Остальные N пунктов заполняет специалист» (M145, Z64); `BriefForm.tsx` — подпись у пустых
   пунктов с `autofill` (M146).
5. Канон (`knowledge/product/brief.md`, инвариант 10), реестр (Z64), стенд: карточка пустого брифа и форма в Chrome.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L260** — число «сколько осталось» считается тем же, что заполняет: остаток — пункты без `autofill` из каталога
  сервера, а не длина каталога.
- **L258, L78** — экран не повторяет правило: что подставлено — `brief_known`, что подставляется вообще — `autofill`
  с сервера; на экране нет ни одного имени пункта.
- **L221** — подстановка в форме — подпись, а не значение поля: иначе сохранение записало бы вывод сервиса как запись
  специалиста (инвариант 10).
- **L240** — id примеров первыми в докстроках и строках тестов.
- **L186** — подменный сервер тестов экрана сличает метод и путь, длиннейший выигрывает.

## Rejected alternatives

- Список с источниками без значений (как в превью вопроса владельцу) — отвергнуто, потому что владелец следом сказал
  «поля, которые должны быть заполнены автоматически, — не заполнены»: ему нужны значения проекта, а источник — серым,
  только когда значения нет.
- Подставлять значение прямо в поле формы — отвергнуто, потому что сохранение записало бы вывод сервиса как запись
  специалиста, и исправленное правило не дошло бы до этого брифа (инвариант 10, Z58).
- Развернуть пустой бриф всеми 22 пунктами — отвергнуто, потому что решение владельца 07.10 — не уводить цифры и
  «Почему эта группа» вниз двенадцатью «заполняет специалист»; остаток — одной строкой.
- Список пунктов на экране константой — отвергнуто, потому что разошёлся бы с правилом на первой новой подстановке
  (Z58, L78).
