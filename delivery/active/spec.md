# Spec: Ф1 — скелет и контракты

## Problem

В проекте есть документы и стабы, но нет каркаса, в который можно писать логику:
ни базы, ни конфига, ни дев-окружения, ни каркасов API и фронта. Писать Ф2
(ядро сбора) без этого — значит по ходу править схему БД и раскладку модулей,
задевая уже написанное.

## Users / stakeholders

Инженер (единственный потребитель этой поставки). Заказчик результата не видит —
это внутренний шаг, и в PHASES_V3 он назван честно: показывать на этой фазе нечего.

## In scope

- Типизированный конфиг по доменам (`config/{ahrefs,storage,auth,classify,export}.py`).
- Модели всех сущностей по `docs/IMPLEMENTATION_V3.md` §4 + первая миграция Alembic.
- `docker-compose.dev.yml`: postgres, redis, api с автоперезагрузкой, vite.
- Каркас FastAPI (health + заготовки роутеров) и каркас React (Vite + Mantine + стекло).
- Раскладка модулей приведена к документу реализации: добавлены `api/`, `workers/`, `web/`.
- CI: линтеры, типы, тесты на каждое изменение.

## Out of scope

- Любая бизнес-логика: сбор, классификация, кейсы. Это Ф2–Ф4.
- Волна В1 (гейты формы CQG) — приходит **в конце** этой фазы, отдельным шагом:
  на пустом репозитории она не проходит собственную приёмку.
- Экраны фронта. Здесь только каркас и визуальный язык.

## Acceptance (observable)

- [ ] `docker compose -f docker-compose.dev.yml up` поднимает postgres, redis, api, vite
- [ ] `alembic upgrade head` применяется на пустой базе и создаёт все таблицы
- [ ] `GET /api/health` отвечает 200 и называет версию миграции
- [ ] `pytest` зелёный; в тестах не участвуют ни сеть, ни живой ключ
- [ ] `mypy --strict src/` без ошибок
- [ ] CI прогоняет линтеры, типы и тесты на push

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| A1 | `alembic upgrade head` на пустой базе, затем `alembic downgrade base` | обе операции без ошибок; после downgrade таблиц проекта нет |
| A2 | `GET /api/health` при поднятой базе | `200`, тело содержит `{"status": "ok", "migration": "<revision>"}` |
| A3 | `GET /api/health` при остановленном postgres | `503` и причина в теле — **не** `200` и не пятисотка без объяснения |
| A4 | импорт `src.ahrefs_cases.config` без файла `.env` | значения из дефолтов, `AHREFS_PROVIDER == "fixture"`, исключения нет |
| A5 | `config.AHREFS_API_KEY` при пустом ключе и `AHREFS_PROVIDER=live` | ошибка на старте с внятным текстом (fail-fast), а не падение при первом запросе |

## Non-functional

- Ядро (`intake/collect/classify/cases/export/storage`) не импортирует ни FastAPI,
  ни RQ. Проверяется тестом на импорты.
- Секретов в репозитории нет; провайдер Ahrefs по умолчанию `fixture`.
- Первый прогон гейтов формы (в конце фазы) обязан быть **красным** либо показать
  непустое число просмотренных файлов — зелёный при нуле означает ненастроенные пути.

## Open questions

- Формула нормализации на длительность работ — нужна к Ф3, не к этой фазе.
- Дедлайн проекта — влияет на состав экранов в Ф6, не на эту фазу.
