# Spec: очередь и запуск прогона по HTTP

Третья поставка Ф5. Прогон перестаёт быть командой в консоли: его запускают из
сервиса, он идёт в фоне, а журнал отвечает, что с ним.

## Problem

Сбор — самая долгая и единственная платная операция сервиса. Запускать её в
обработчике HTTP нельзя: запрос оборвётся по таймауту раньше, чем прогон
закончится, а перезапуск по кнопке стоит units заказчика.

Второе требование ТЗ прямое: **два одновременных прогона не должны мешать друг
другу**. Запускают шесть-семь человек из четырёх отделов, и «я тоже нажал»
обязано быть отказом с понятной причиной, а не вторым прогоном по тем же
доменам за двойную цену.

Третье: Redis на машине разработчика может не быть, а работать сервис должен.
Поэтому очередь — интерфейс с двумя реализациями, как провайдер Ahrefs.

## In scope

- `workers/queue.py` — `JobQueue` с двумя реализациями: `InlineQueue`
  (выполняет сразу, для разработки и тестов) и `RedisQueue` (RQ), выбор по
  конфигу.
- `workers/jobs.py` — задачи: прогон сбора и сборка пачки кейсов. Аргументы —
  простые значения: задача уезжает в другой процесс.
- `api/routers/runs.py` — `POST /api/runs` (право `run`), `GET /api/runs`,
  `GET /api/runs/{id}`.
- Замок: пока прогон в очереди или идёт, второй не ставится — `409` с номером
  активного.

## Out of scope

- **Уведомления** (Telegram/Asana) о готовности ZIP и упавшем прогоне — вместе
  с алертами в следующей поставке.
- **Отмена прогона** — ТЗ не требует; реапер зависших уже есть в `collect`.
- Приоритеты и несколько очередей — при одном воркере это украшение.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | `POST /api/runs` без токена | `401` |
| E2 | `POST /api/runs` пользователем | `202` с номером прогона: право `run` есть у всех трёх групп |
| E3 | второй `POST /api/runs`, пока первый не закончен | `409` с номером активного прогона, а не второй прогон |
| E4 | `GET /api/runs` | журнал: статус, сколько проектов, сколько units |
| E5 | `GET /api/runs/{id}` несуществующего | `404` |
| E6 | inline-очередь | задача выполняется в том же процессе: разработка без Redis работает |
| E7 | упавшая задача | прогон в журнале помечается `failed` с причиной, а не остаётся «идёт» навсегда |
| E8 | задача сборки кейсов | ставится той же очередью и пишет свой прогон |
| E9 | выбор очереди | по конфигу, как провайдер Ahrefs: одно место решает |
| E10 | аргументы задачи | простые значения (числа и строки), потому что задача уезжает в другой процесс |

## Non-functional

- Задача не держит сессию вызывающего: у воркера своя.
- В fixture-режиме прогон не ходит в сеть и не тратит units.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- Замок пока глобальный: прогон идёт по всему списку проектов. Когда появятся
  выборочные прогоны (по набору доменов), он сузится до набора — и это будет
  видно в API, а не в поведении.
