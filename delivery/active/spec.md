# Spec: экран «Пороги» — действующие пороги словами

## Problem

Пороги решают, какой проект «хороший», а какой «средний», то есть **какие кейсы
уйдут клиентам**. Версии, значения и последствия сейчас видны только через API:
`/thresholds` — заглушка.

Хуже того, значения живут JSON'ом (`groups.good.org_traffic.growth_pct_min`), а
утверждают их Head of Link Building и Owner — люди, которым JSON не показывают.

Предпросмотр («кто сменит группу, если применить эту версию») в API есть и
открыт праву `read` нарочно: на калибровке этот вопрос задают десятки раз
подряд и обсуждают втроём. Из интерфейса задать его нельзя.

## In scope

- Экран «Пороги»: действующая версия **словами** — условия «хорошего» и
  «среднего», пригодность, ограничитель.
- Показывается **действующая** версия: та, по которой посчитаны вердикты на
  остальных экранах. Свежая версия не обязательно действующая — сохранение не
  активирует.
- Раздел остаётся под правом `edit_thresholds` — **как в таблице доступа ТЗ**
  («Пользователь: пороги — нет»). Открытый предпросмотр в API это не отменяет:
  правом `read` его можно спросить, но отдельного экрана у того, кто пороги не
  утверждает, по ТЗ нет. Расширять таблицу — решение заказчика.
- Значения, которые здесь не правятся (окна точек, веса счёта, нормализация на
  длительность), показаны и **помечены**: скрытое поле читается как отсутствующее.
- Состояния: грузится, пусто, отказ сервера — у каждого свой текст.

## Out of scope

- **Список версий и предпросмотр последствий** — следующая поставка
  `thresholds-preview`: «что изменится» это отдельный вопрос и отдельный расчёт
  на сервере.
- **Правка порогов, сохранение версии, активация, пересчёт** — поставка
  `thresholds-edit`: форма под правом `edit_thresholds`.
- Сравнение двух версий между собой: на калибровке хватает предпросмотра
  относительно текущих вердиктов.
- Нормализация на длительность работ: формулы от заказчика нет, ненулевое
  значение отказывает на разборе — экран это показывает, но не чинит.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | две версии, активна старшая | показана действующая, а не свежая |
| E2 | действующая версия | условия групп словами: проценты, визиты, месяцы |
| E5 | версий нет | «классифицировать нечем», а не пустая карточка |
| E6 | сервер ответил отказом | текст сервера |
| E7 | `normalize_after_months: 12` | сказано, что блок не реализован и версия не примется |
| E8 | `or_high_pct_low_abs: true` | вилка «средних» названа словами, а не флагом |
| — | ноль в ограничителе | «не задано», а не порог, равный нулю |

## Non-functional

- Внутренние значения переводятся (`period` → «период работ»), незнакомое
  показывается как есть: подмена словом соврала бы про версию.
- Узкий экран: таблицы прокручиваются.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- Какие поля попадут в форму правки (следующая поставка): предлагаю править то,
  что решает группу — условия групп, пригодность, ограничитель, — а окна точек и
  веса счёта оставить только на просмотр, потому что они меняют смысл данных, а
  не границу. Решается перед `web-thresholds-edit`.
