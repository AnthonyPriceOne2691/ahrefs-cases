# Spec: журнал прогонов и расход units

## Problem

Прогон идёт часами в фоне. Человек, нажавший кнопку, знает только номер; узнать,
дошёл ли прогон до конца, чем кончился и сколько съел, можно лишь через API.
Расход units — единственный платный ресурс сервиса — не показан нигде, хотя
заказчик назвал стоимость запуска метрикой успеха, а остаток квоты — поводом для
алерта.

## In scope

- Экран «Прогоны»: журнал — номер, статус, время, проекты (успешно из всего),
  смета и факт в units, причина падения.
- **Идущий прогон обновляется сам**, пока не закончится; закончившийся —
  перестаёт опрашиваться.
- Экран «Расход units»: потрачено, удержано резервом, остаток, стоимость запуска
  на сто доменов.
- **Алерты на экране расхода**: остаток, упавшие прогоны, готовая пачка. Четыре
  степени (`critical`, `serious`, `warning`, `good`) выглядят по-разному, а
  пустой список говорит «поводов нет», а не молчит.
- Остаток, которого не узнали, показан как «неизвестен», а не как ноль.
- Состояния: грузится, пусто, отказ сервера — у каждого свой текст.

## Out of scope

- **Запуск прогона с этих экранов**: кнопка живёт на «Загрузке», рядом со
  сметой. Вторая кнопка означала бы вторую дверь к тратам.
- Остановка идущего прогона: в API этого нет, и придумывать здесь нельзя.
- Доставка алертов в Telegram или Asana: это Ф9 вместе с настройкой каналов.
- Разбор расхода по endpoint'ам: он есть в отчёте прогона в консоли, а на
  экране потребовал бы своего API.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | три прогона в журнале | строки со статусом, проектами и units |
| E2 | прогон со статусом `running` | журнал перезапрашивается сам |
| E3 | все прогоны завершены | опрос прекращается |
| E4 | упавший прогон | причина видна в строке, а не «ошибка» |
| E5 | журнал пуст | «прогонов ещё не было», а не пустая таблица |
| E6 | расход: потрачено и резерв | числа на экране, остаток отдельно |
| E7 | остаток неизвестен | «неизвестен», а не ноль |
| E8 | алерт `units_low` | виден как критический, с числом из сообщения |
| E9 | алертов нет | «поводов нет» — проверили, чисто |
| E10 | сервер ответил отказом | текст сервера |

## Non-functional

- Опрос идущего прогона — раз в пять секунд, и только пока он идёт: постоянный
  опрос фонового процесса дороже, чем польза от секунды точности.
- Узкий экран: таблица прокручивается.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- «Кто запустил» показывается идентификатором: имена людей есть в API людей, и
  тянуть их сюда ради колонки значит связывать два экрана. Решается вместе со
  страницей «Люди».
