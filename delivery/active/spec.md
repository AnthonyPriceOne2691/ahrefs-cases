# Spec: журнал пишет домен по-человечески и называет режим прогона

## Problem

1. Раскрытие судеб прогона показывает кириллические домены каноном:
   `xn--mller-shop-9db.de`, `xn----7sbbfcp9amtfeggde.example`. Канон нужен
   Ahrefs и базе; человек читает его как ошибку сервиса (урок L131). Кейс уже
   пишет домен по-человечески — правило 4а, `intake.normalize.to_unicode`.
2. Журнал не называет режим прогона. У fixture-прогона «смета → факт» —
   условные units: в Ahrefs он не ходил, «потрачено» их уже не считает (Z38),
   а в журнале они выглядят как настоящий расход.

## In scope

- Судьба прогона в ответе `/api/runs/{id}` и на экране — домен в виде, в
  котором его пишет человек, тем же `to_unicode`; второй копии правила нет.
- Строка журнала (`/api/runs`, `/api/runs/{id}`) несёт режим: `live` — по тому
  же предикату, что считает расход (`budget._live_run`), и `mode` — записанный
  режим для слова.
- Экран журнала под «смета → факт» говорит, что units условные у
  fixture-прогона, и что режим не записан у старого прогона.

## Out of scope

- Домен каноном на других экранах (список проектов, карточка, библиотека
  кейсов, удаление, список внутри ZIP) — запись в реестр (Z47): поиск списка
  проектов сравнивает канон, и смена вида там требует и поиска по виду.
- Текст причины из ответа Ahrefs (в нём домен каноном — так его отправили).
- `collect/run_journal.py` — не трогается: там идёт работа другого агента.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| W1 | Прогон с судьбой проекта `xn--mller-shop-9db.de` (нет данных) | в ответе `/api/runs/{id}` домен судьбы — `müller-shop.de`; раскрытие показывает `müller-shop.de` |
| W2 | Судьба с хостом, который обратно не разбирается (`xn--zz.example`) | показан как есть, каноном (правило 4а: уронить журнал хуже) |
| W3 | Прогон, открытый в режиме fixture (`params_snapshot.provider = fixture`) | в ответе `live: false`, `mode: "fixture"`; под «смета → факт» — «условные units: прогон без живого ключа (fixture)» |
| W4 | Живой прогон (`provider = live`) | `live: true`, `mode: "live"`; пометки нет |
| W5 | Прогон без режима в снимке (старый) | `live: false`, `mode: ""`; «режим не записан — units не считаются расходом» |
| W6 | Три прогона (live, fixture, без режима) со строками расхода | `live: true` ровно у того, чей расход считает «потрачено» (`budget.spend_summary`): одно правило |

## Non-functional

- Слова — на экране, решение «живой ли» — на сервере одним предикатом (L78).
- Лишнего на экране нет: живой прогон ничем не помечен (прод весь живой).
