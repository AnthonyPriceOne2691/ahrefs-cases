# Spec: кампании одного домена платят за месяц один раз

## Problem

Один сайт агентство ведёт несколькими кампаниями — это норма, и проект
опознаётся тройкой `(домен, режим, начало периода)`. Ряды при этом лежат в
`metric_points` с `project_id`, и весь кэш — «закрытый месяц неизменяем» —
спрашивает только свой проект. Перекрывающиеся месяцы второй кампании
покупаются заново: 209 units на лишнюю историю по профилю ТЗ.

Нарушено первое правило ТЗ и конституции: ни один запрос к Ahrefs не делается
дважды за одни и те же данные.

## In scope

- **План не заказывает дважды.** Реестр уже заказанного внутри плана: месяц,
  который просит соседняя кампания того же домена и режима, второй раз не
  заказывается. Экономия попадает в **смету** — её сверяет `preflight`.
- **База раздаёт купленное.** Перенос точек между кампаниями одного домена и
  режима: до планирования (что куплено прошлыми прогонами) и после сбора (что
  куплено этим). Кампания, чьи месяцы купил сосед, получает свою серию целой.
- **Перенос ограничен отрезком проекта** (`scheme.history_span`): иначе давняя
  кампания растягивает серию назад и создаёт в ней дыру.
- **Z15, найденный живым прогоном:** `--only` сверяет множества доменов, а не
  длины списков; `explain` и `diagnose` разбирают каждую кампанию.

## Out of scope

- **Ключ серии по домену вместо проекта** (миграция). Полное решение, которое
  сделало бы перенос ненужным: одни ряды на домен + режим, кампании смотрят на
  свои отрезки. Это отдельная поставка с миграцией данных и правкой всех
  читателей серий; сейчас важнее, чтобы деньги перестали тратиться дважды.
- **Перенос между режимами подсчёта.** `subdomains` и `prefix` — разные числа
  по построению, и подмена была бы видна только по величине.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | две кампании одного домена в одном прогоне | каждый месяц заказан один раз |
| E2 | кампания целиком внутри другой | ни одного запроса, причина названа словами |
| E3 | кампания, чьи месяцы купил сосед | своя серия целая, без дыр |
| E4 | давняя кампания того же домена | её месяцы не переносятся: вне отрезка |
| E5 | тот же домен в режиме `prefix` | перенос не делается |
| E6 | `collect --only` по домену с двумя кампаниями | прогон идёт, а не падает |
| E7 | `explain` по домену с двумя кампаниями | обе, с периодами |

## Non-functional

- Ни одного нового запроса к Ahrefs; перенос — запрос к своей базе.
- Число перенесённых месяцев печатается в отчёте прогона: молчать об экономии
  нельзя, иначе «почему второй прогон дешевле» останется без ответа.

## Open questions

- Стоит ли переносить точки **между режимами**, когда `prefix` вложен в
  `subdomains`. Ответ не очевиден и стоит замера: числа разные, но связанные.
