# Spec: прогон рассказывает, что случилось с каждым доменом

## Problem

`run_items` заполняется с первой поставки Ф2: проект, исход, причина, units.
Наружу не выходит ничего. Экран прогонов показывает «17 из 19» и молчит о
пропущенных — а пропуск бывает четырёх видов, и действия по ним разные:
докупить историю, поправить строку списка, поднять лимит units, перезапустить.

## In scope

- `GET /api/runs/{id}` отдаёт судьбу доменов: домен, исход, причина, units.
- В строке прогона появляется `projects_skipped` — счётчик, которого не было
  ни в модели ответа, ни на экране.
- Экран прогонов показывает пропуски строкой с причиной, а не только числом.
- Выдача ограничена: список не растёт с корпусом, у прогона максимум сто
  проектов, и на каждый не больше одной записи на endpoint.

## Out of scope

- Кнопка «перезапустить пропущенные»: это трата units, и решение о ней
  принимает владелец после первого боевого прогона.
- Отчёт по прогону файлом (CSV) — ТЗ его не требует, экрана достаточно.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | прогон, где домен пропущен без данных | в карточке прогона домен и причина |
| E2 | тот же прогон | `projects_skipped` = 1, и это видно в списке прогонов |
| E3 | прогон без пропусков | список пуст, экран не показывает лишнего |
| E4 | прогон с сотней записей | выдача ограничена и не зависит от размера базы |
| E5 | нет права `read` | 403, как у остальных чтений |

## Non-functional

- Один запрос на карточку прогона: судьбы читаются вместе со строкой прогона.
- В списке прогонов — один групповой запрос на страницу, а не по запросу на строку.
