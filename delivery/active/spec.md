# Spec: удалённый и заново загруженный проект — без повторных покупок и без слитых судеб (Z40, Z41)

## Problem

- **Z40, деньги.** Память о пустом домене (`cache.empty_since`) держится за номер проекта в журнале прогонов. Удаление
  проекта обнуляет этот номер (`ON DELETE SET NULL`), и у загруженного заново проекта памяти нет: домен, дважды
  подтверждённый пустым, покупается снова — вживую от 50 units за запрос, и подтверждается дважды заново.
- **Z40, подпись прочерка.** «Что по домену покупали» (`purchases.bought_metrics`) читается из журнала расхода по
  домену, а журнал удаление переживает: у заново загруженного проекта до его шага 2 прочерк подписан «нет у Ahrefs» —
  по покупке удалённого, — хотя для нового проекта шаг 2 не делался.
- **Z41, журнал.** У строки журнала удалённого проекта остаются домен, исход и units; две удалённые кампании одного
  сайта из одного прогона сливаются в одну судьбу — на копии дев-базы прогон 1088 показал `nordvpn.com` одной строкой
  «ok, 264» вместо двух по 132.
- **Z41, консоль.** Удаление в миллисекунды между загрузкой проектов и открытием консольного прогона роняло его. С #58
  консоль берёт тот же замок постановки, что кнопка и удаление, — окно закрыто по коду, теста на него нет.

## In scope

- Память о пустом домене учитывает и строки журнала удалённых проектов того же домена; у двух живых кампаний сайта
  она по-прежнему своя у каждой.
- «Что покупали» считает только покупки для проектов этого домена, которые есть сейчас.
- Строка журнала помнит номер проекта и после его удаления (`run_items.project_ref`, без внешнего ключа); судьбы
  удалённых кампаний различаются по нему. Старые строки получают его из `project_id`, где он ещё есть.
- Тест на окно консоли: удаление во время консольного сбора ждёт замка и отказывает «идёт прогон».

## Out of scope

- Оплаченные ряды по-прежнему уходят с удалённым проектом (решение владельца 24.09.2026).
- Строки журнала, удалённые до этой поставки, номера не вернут: `project_id` у них уже пуст.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| M105 | Домен дважды ответил пустой историей; проект удалён и загружен заново | следующий сбор провайдера не спрашивает: судьба «из памяти», как у проекта, который не удаляли |
| M106 | Две живые кампании сайта; у первой два пустых ответа, вторая не проверялась | память включается только у первой; вторую сбор спрашивает |
| M107 | Шаг 2 удалённого проекта купил ряды и Ahrefs их не отдал; проект загружен заново, его шаг 2 не делался | прочерк нового проекта — «не собирали»; у живой кампании того же сайта, чей шаг 2 прошёл без данных, — «нет у Ahrefs», как прежде |
| M108 | Две кампании одного сайта в одном прогоне, по 132 units; обе удалены | в журнале прогона две строки судеб по 132, а не одна на 264 |
