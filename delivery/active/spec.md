# Spec: скриншоты проектов — хранение и обработка (сервер, часть 1)

## Problem

Команда агентства 07.10.2026: «Полуавтомат со скриншотами Ahrefs — согласны. Готовые ссылки на
отчёты… + загрузка скрина в карточку проекта»; «AI-инструменты: экраны видимости бренда в
ChatGPT/Perplexity/Google AI Overviews». Владелец 07.10: «пилу для скриншотов говорю да» (Pillow).

Ссылки на отчёты в брифе есть с #51, а скрину негде жить: ни таблицы, ни места на диске, ни
проверки, что пришла картинка, а не что угодно под именем `.png`.

## In scope

- Прямая зависимость `pillow` (стояла транзитивно через WeasyPrint, версия та же — 12.3.0).
- `storage/screenshots.py`: формат по содержимому (PNG, JPEG, WebP), площадь до распаковки,
  ужатие длинной стороны до 2000 px, перекодирование без метаданных, прозрачное — на белом;
  файлы под нашим именем `<проект>/<uuid>` в `data/screenshots`, запись через временный файл,
  чтение и удаление не выходят из каталога, удаление каталога проекта.
- Таблица `project_screenshots` (миграция `d1e2f3a4b5c6`): вид (`ahrefs` / `ai`), подпись, ключ
  файла, тип, размеры, сумма, кто загрузил; каскад с проектом; одна картинка у проекта — один раз.
- Каталог в настройках (`EXPORT_SCREENSHOTS_DIR`), в `.gitignore`, в описании бэкапа.

## Out of scope

- API загрузки, списка, просмотра и удаления; удаление файлов вместе с проектом — следующий PR.
- Скрины в PDF — PR после него; экран загрузки — последний.

## Acceptance examples
