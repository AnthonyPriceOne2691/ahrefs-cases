# Spec: колонки брифа во входном файле и NDA при повторной загрузке

## Problem

Команда агентства 07.10.2026: «Ручные поля „запрос клиента“ (свободный текст) и
„сложность“ (список + комментарий), дублируемые в необязательные колонки входного
файла, — ок»; ниша — «Тематика» + «Тип сайта» из списков; папка — ссылкой на Google
Drive. Владелец 07.10 на вопрос «повторная загрузка файла молча снимет флажок NDA,
поставленный в карточке»: «давай как советуешь» — файл может поставить NDA, снять —
только карточка.

С #48 бриф хранится и правится через API, но файлом его не заполнить, а повторная
загрузка переписывает `publishable` — то есть молча снимает NDA.

## In scope

- Шесть необязательных колонок брифа: `topic`, `site_type`, `client_request`,
  `complexity`, `complexity_note`, `folder_url` — список задаёт описание брифа.
- Непонятая ячейка брифа — замечание (`bad_enum`, `bad_link`, `too_long`), строка принята.
- Пустая ячейка не стирает записанное в карточке; файл бриф дополняет.
- NDA: «нет» в файле ставит, «да» не снимает.
- Подсказка экрана к файлу и тексты замечаний; исправлена старая неправда подсказки
  («пустое `publishable` читается как „нет“» — приём отклоняет пустую ячейку).

## Out of scope

- Форма брифа в карточке — поставка 2б. Лист PDF — этап 3.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| M24 | Строка файла: «Путешествия», «маркетплейс», запрос клиента, «Высокая», комментарий, ссылка на Drive | строка принята без замечаний; бриф черновика: `travel`, `marketplace`, текст, `high`, комментарий, ссылка |
| M25 | «космодром» в типе сайта, «адская» сложность, ссылка на Яндекс.Диск | строка принята; в брифе только понятое; замечания `bad_enum` (со словом «космодром»), `bad_enum`, `bad_link` (с адресом) |
| M26 | В карточке записаны цели и запрос клиента; файл приходит с пустым запросом и типом сайта «SaaS» | запрос и цели из карточки на месте, тип сайта — `saas` |
| M27 | Проект под NDA из карточки, файл «да»; затем проект открыт, файл «нет» | NDA остаётся; затем NDA ставится |
