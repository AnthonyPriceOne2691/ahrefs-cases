# Spec: приём файла объясняет, каким он должен быть, и не берёт неподходящий

## Problem

У поля «Ссылка на Google Sheet» стоит «?» с описанием колонок, у поля «Файл со
списком» — нет: чтобы узнать, каким должен быть файл, человек идёт к соседнему
полю, которое не про файл.

Файл, который не годится целиком, принимается «успешно». Файл без нужных
колонок (шапка по-русски, чужой разделитель, `Period Start` вместо
`period_start`, список не на первом листе) отвечает `200`, экран пишет «Принято
из «файл.csv»», «принято 0» и таблицу «в файле нет колонки» — ошибка файла
выглядит как успешный приём. Только шапка без строк — тоже «Принято». Книга,
которая не читается (PDF, переименованный в `.xlsx`), роняет сервер `500`.
Таблица по ссылке идёт тем же путём и ведёт себя так же.

## Users / stakeholders

PR-отдел и руководители, загружающие список без консоли; инженер, запускающий
`intake` командой.

## In scope

- «?» у «Файл со списком»: колонки с примерами — те же, что у Google Sheet, и
  своё про файл (форматы, первый лист, разделитель и кодировка CSV, 2 МБ).
  Описание колонок одно на обе подсказки и сверено с сервером.
- Граница «брак файла / брак строки». Брак файла — отказ `400` с человеческим
  текстом (что не так, что прочитано, какие колонки ожидаются), в базу не
  пишется ничего. Брак строк в подходящем файле — отчёт, как прежде.
- То же правило для таблицы по ссылке — требование владельца, а не «по
  возможности». Отказ доступа (закрытая таблица) остаётся своей причиной.
- Экран: отказ — красной плашкой у того поля, которым список давали.
- Командная строка: неподходящий список — код 2 и причина, а не отчёт.

## Out of scope

- **Предел числа строк.** ТЗ объявляет «до 100 проектов за одну загрузку»
  (`knowledge/product/overview.md`), но как объём, а не правило приёма: прогон
  и смета считают всю базу, а не последнюю загрузку, и предел на загрузку
  обходится вторым файлом — ничего не ограничивая. Траты держит смета с квотой.
- **Русские имена колонок и `Period Start` как `period_start`.** Принимать их —
  расширять формат, это другое решение. Отказ показывает прочитанное и
  подсказывает ближайшее верное имя.
- **Поиск списка на других листах и шапки ниже первой строки.** Отказ называет
  прочитанный лист и остальные листы книги.
- **Проверка на клиенте до отправки** — кроме размера. Остальное было бы
  второй копией правил сервера; правду говорит сервер, фильтр `accept` у выбора
  файла остаётся подсказкой. Размер — исключение, найденное исполнением (V22):
  ответ сервера `413` через прокси до человека не доходит, а предел берётся из
  тех же данных, что сверены с сервером тестом.

## Acceptance examples

Брак файла — отказ `400`, проектов из файла в базе нет:

| # | Вход | Ожидаемый выход |
|---|---|---|
| V1 | XLSX без колонок `period_start` и `geo` | «Файл «список.xlsx» не подходит: нет колонок period_start, geo» и перечень всех ожидаемых |
| V2 | CSV с шапкой по-русски («домен», «начало», …) — в UTF-8 и в cp1251 с `;` | отказ: нет всех десяти; текст показывает прочитанное («домен», …) и ожидаемые имена латиницей |
| V3 | CSV с разделителем `\|` | отказ; в тексте прочитанная первая строка одной ячейкой «domain\|period_start\|…» |
| V4 | шапка `Period Start`, `Period End`, `Service Type`, `Work Volume` | отказ с подсказкой «period_start — в шапке «period start», переименуйте» по каждой из четырёх |
| V5 | только шапка; шапка и пустые строки | отказ «только шапка — строк со списком нет» |
| V6 | пустой файл (0 байт) | отказ «файл пуст» — без слов «тело запроса» |
| V7 | книга: первый лист пуст или с инструкцией, список на втором «Список» | отказ называет прочитанный первый лист и «Список» — перенести на первый |
| V8 | PDF, CSV или DOCX, переименованные в `.xlsx`; обрезанная книга | отказ «не читается как книга Excel» вместо `500` |
| V9 | книга XLSX или PDF, переименованные в `.csv` | отказ «не похож на текст» вместо «Принято» с мусорной шапкой; длинная двоичная строка — отказ вместо `500` |
| V10 | колонка `domain` в шапке дважды | отказ «domain встречается дважды» вместо молча взятой последней |
| V11 | `.pdf` по расширению; тело больше 2 МБ, присланное в API напрямую | как прежде: `400` «не понимаю формат», `413` с пределом |

Брак строк — отчёт, как прежде:

| # | Вход | Ожидаемый выход |
|---|---|---|
| V12 | подходящий XLSX: десять годных строк и одна без домена | `200`, принято 10, строка 12 — «пустое обязательное поле» |

Ссылка на Google Sheet — то же правило:

| # | Вход | Ожидаемый выход |
|---|---|---|
| V13 | таблица по ссылке без `client` и `owner` | `400` «Таблица по ссылке не подходит: нет колонок client, owner» и перечень ожидаемых |
| V14 | лист по ссылке пуст; только шапка; шапка по-русски | `400` с той же причиной, что у файла; у пустого листа и у шапки без единой нужной колонки — «читается лист из ссылки (gid=…)» |
| V15 | закрытая таблица (страница входа, статус 200) | `400` «таблица недоступна по ссылке» — своя причина, а не «не подходит» (L10) |

Экран и командная строка:

| # | Вход | Ожидаемый выход |
|---|---|---|
| V16 | отказ по файлу | красная плашка с текстом сервера под полем файла; «Принято из …» и таблицы отказов нет |
| V17 | отказ по ссылке | красная плашка под полем ссылки, а не под файлом |
| V18 | «?» у «Файл со списком» («каким должен быть файл») | колонки с примерами — те же, что у Google Sheet; про файл: XLSX/XLSM или CSV до 2 МБ, первый лист, разделитель и кодировка CSV; абзаца про доступ по ссылке нет |
| V19 | колонки обеих подсказок | один список данных; совпадает с сервером — обязательные, необязательные, «можно пустым», форматы файла и предел; расхождение краснит тест |
| V20 | ответ пришёл (любой), выбран тот же файл | уходит новый запрос; сейчас повторный выбор того же файла в Chrome не делает ничего |
| V21 | `run_collect.py intake` на файле без колонок | код 2, «список не подходит: …» в stderr; сейчас код 1 и отчёт с десятью `missing_column` |
| V22 | на экране выбран файл больше 2 МБ (добавлен на converge: найден исполнением) | отказ у поля файла, запрос не уходит; прежде сервер отвечал `413`, прокси рвал соединение (`EPIPE`) и экран писал «сервер ответил 500» |

## Non-functional

- Отказ случается до записи: база после него та же, что до.
- Тексты отказов по-русски, называют прочитанное и ожидаемое; имена колонок
  собираются из констант сервера, а не пишутся второй раз.
- Отказ — тот же код `400`, что у остальных отказов приёма (формат, ссылка).
