# Spec: экран проектов — таблица, фильтры, группы

## Problem

Список проектов и их группы существуют только по HTTP. Сотрудник, загрузивший
сотню доменов, не может посмотреть, что из них вышло: раздел «Проекты»
показывает заглушку.

Экран нужен не «чтобы был»: по нему решают, какие проекты пойдут в кейсы, и
именно здесь человек впервые видит результат классификации. Значит он обязан
показывать группу и то, насколько уверенно она получена, а не только домены.

## In scope

- Таблица проектов на TanStack Table: домен, ниша, гео, период работ, группа,
  счёт, «можно публиковать».
- Фильтры: по группе и поиск по домену. Оба уходят на сервер — он умеет оба, и
  фильтровать страницу на клиенте значило бы врать при пагинации.
- Пагинация: сервер отдаёт не больше сотни строк за раз, экран это уважает.
- **Четыре группы, а не три**: «нет данных» — своя, не «плохой». Цвет каждой из
  `theme.groupInk` — тот же источник, что у графиков и плиток.
- Непроклассифицированный проект (группы нет вовсе) показан честно: «не
  классифицирован», а не пустая ячейка.
- Состояния экрана: идёт загрузка, пусто, отказ сервера — у каждого свой текст.
- Строка ведёт на карточку `/projects/:id`; сам экран карточки — следующая
  поставка, до неё там честная заглушка.

## Out of scope

- **Карточка проекта** — следующая поставка (`web-project-card`).
- Сортировка на сервере: API отдаёт по домену, и второй порядок потребовал бы
  своего параметра и своей проверки границ.
- Выгрузка таблицы в файл: ТЗ этого не просит, а кейсы и так уходят ZIP-ом.
- Массовые действия над выбранными проектами: их нет в ТЗ.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | три проекта с разными группами | три строки, у каждой свой цвет группы |
| E2 | проект без вердикта | «не классифицирован», а не пустая ячейка |
| E3 | проект в группе «нет данных» | отличается от «плохого» и словом, и цветом |
| E4 | выбран фильтр «хорошие» | запрос уходит с `group=good`, таблица перерисовывается |
| E5 | введён кусок домена | запрос уходит с `query=…` |
| E6 | сервер отдал пусто | «ничего не нашлось» с подсказкой снять фильтры |
| E7 | проектов нет вовсе | текст про загрузку списка, а не «ничего не нашлось» |
| E8 | сервер ответил `403` | текст сервера, а не «что-то пошло не так» |
| E9 | строк больше страницы | листание вперёд и назад, номер страницы виден |
| E10 | клик по строке | адрес меняется на `/projects/:id` |

## Non-functional

- Фильтры не сбрасывают страницу молча: смена фильтра возвращает на первую
  страницу, и это видно.
- Узкий экран: таблица прокручивается, а не ломает раскладку.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- «Счёт» показывается числом как есть. Что он значит для человека — объясняет
  карточка через условия вердикта; в таблице это ориентир, а не оценка.
