# Spec: ступень кейса — докупка под графики и числа

Последняя поставка по сбору. Дальше Ф4 берёт готовые данные и собирает PDF.

## Problem

Кейс и вердикт хотят разного. Вердикту хватает двух точек, кейсу нужны кривые:
ТЗ прямо требует «динамику трафика» и «динамику позиций» с отметкой старта
работ, и прямо называет гранулярность **месячной**.

Сегодня после шага 2 позиции есть только в двух точках — их покупка двумя
окнами и дала главную экономию прогона. Кривой из двух точек не бывает:
сгладить её значило бы нарисовать месяцы, которых мы не мерили.

Ещё два долга из must-have списка ТЗ: **traffic value** (убран с шага 1, потому
что второе поле удваивало цену строки всем ста доменам) и **число ключей**.

## In scope

- **Ступень кейса**: докупка только для проектов, у которых вердикт `good` или
  `medium` — то есть после классификации, а не до.
- **Узкий набор полей для кривой позиций**: `top3` и `top4_10` вместо пяти
  корзин. Цена строки падает с 51 до 21, середина периода — с 765 до 315.
  Полное распределение (топ-3 / топ-10 / топ-100) остаётся в точках А и Б,
  где оно уже куплено шагом 2.
- **Traffic value двумя точками**: в кейсе это число, а не кривая.
- **Докупка середины, а не всей истории**: месяцы на границах уже есть, и
  платить за них второй раз незачем.
- **Правило агрегации по типу метрики** — для тумблера разрешения в Ф6 и для
  выбора масштаба в PDF: поток суммируется, запас берётся на конец периода.

## Out of scope

- Сами графики, PDF и ZIP — Ф4. Здесь только данные под них.
- Тумблер разрешения на экране — Ф6; правило агрегации пишется здесь, чтобы
  экран не изобретал его заново.
- `DR`, `pages`, `search_volume` — остаются под флагами: читателя у них нет.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | ступень кейса по проекту с 18-месячным периодом | докупается **середина** (15 строк), а не весь период: 315 units вместо 399 |
| E2 | цена строки кривой позиций | 21, а не 51: в запросе два поля вместо пяти — и это видно в `select` |
| E3 | распределение позиций в кейсе | топ-3 / топ-10 / топ-100 на границах периода полные: середина не обязана их знать |
| E4 | traffic value | покупается двумя точками (100 units), а не историей (209): в кейсе это число |
| E5 | ступень запускается по вердиктам | берёт только `good` и `medium` по действующей версии порогов; «плохие» и `insufficient_data` не стоят ничего |
| E6 | кэш и watermark | ступень **не** обманывается watermark'ом: серия с дырой в середине не считается собранной (урок L27) |
| E7 | повторный запуск ступени | ничего не докупает: середина уже есть |
| E8 | смета ступени на десяти кейсах | 4 150 units; в отчёте видно, за что именно платим |
| E9 | агрегация для тумблера | поток (трафик) за квартал — сумма месяцев; запас (ссылки, ключи в топе) — значение на конец квартала. Одно правило на обе группы завысило бы запас втрое |

## Non-functional

- Ступень не покупает ничего проектам без кейса: проверяется числом запросов.
- Кривая рисуется **по измеренным точкам**: интерполяции и сглаживания нет ни
  в данных, ни в правиле агрегации.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- «Число ключей» из must-have списка ТЗ равно сумме пяти корзин распределения —
  это свойство API, а не наше решение, и замером оно не подтверждено. Пока
  считаем суммой и записываем гипотезой в реестр находок.
