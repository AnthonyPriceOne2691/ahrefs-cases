# Spec: Ф2а — приём списка и сбор на фикстурах

Первая половина Ф2 из `docs/PHASES_V3.md`. Вторая (Ф2б) — экономия units:
кэш закрытых месяцев, инкрементальный `date_from`, single-flight, смета,
preflight квоты, двухступенчатая воронка.

## Problem

Ф1 дала каркас без единой строки бизнес-логики: есть таблицы, но в них нечего
класть. Ф3 (классификация) и Ф4 (кейс) не с чем разрабатывать — им нужны серии
метрик с заранее известной формой, а живого ключа нет и до Ф7 не будет.

Без этой поставки любая работа над классификацией опирается на данные, которые
исполнитель придумывает по ходу теста, — то есть на ожидания, никем не
подписанные.

## Users / stakeholders

Инженер. Заказчик результата по-прежнему не видит: наблюдаемый выход поставки —
строки в базе и отчёт о прогоне, не PDF.

## In scope

- **`intake`** — чтение списка проектов из CSV, XLSX и Google Sheet
  (по ссылке на опубликованную таблицу, через CSV-экспорт; сервисный аккаунт —
  не здесь). Проверка десяти обязательных полей, нормализация домена в
  канонический хост, построчный отчёт по забракованному.
- **`config/projects.example.csv`** приводится к десяти обязательным полям
  §4 документа реализации: сейчас в нём семь колонок и нет `service_type`,
  `work_volume`, `client`, `owner`, `publishable`.
- **Провайдер за `Protocol`**: `AhrefsFixture` (записанные и синтетические
  ответы) и `AhrefsLive` (пишется сразу, до Ф7 не проверяется). Выбор по
  `AHREFS_PROVIDER`, не по коду.
- **Спеки шести history-endpoint'ов данными, а не кодом** — имя, `select`,
  ключ списка в ответе, модель стоимости.
- **Генератор синтетических серий** по семи сценариям §1a: явный рост, слабый
  рост, падение, короткая история, дыра в данных, провал в конце, скачок
  ссылочного. Детерминирован по seed.
- **Прогон**: шаг 1 (`metrics-history`) по всем проектам списка, `MetricPoint`
  в базе, `RunItem` на каждый проект, `Run` со статусом и отчётом.
- **`UnitsLedger`**: строка на каждый запрос к провайдеру, в fixture-режиме
  units условные, посчитанные по той же модели стоимости, что применит live.

## Out of scope

- Кэш «закрытые месяцы неизменяемы», инкрементальный `date_from`, дедупликация
  между прогонами, single-flight — **Ф2б**. Здесь прогон честно перезапрашивает
  всё; иначе главный DoD Ф2 («повторный прогон не делает повторных запросов»)
  проверялся бы кодом, написанным в той же поставке, что и тест.
- Смета до запуска, резервы, preflight квоты, мягкий стоп — Ф2б.
- Шаг 2 воронки (`keywords-history`, `refdomains-history`, срезы) — Ф2б: без
  предварительной группы отбирать кандидатов нечем.
- Классификация — Ф3. Прогон складывает серии и молчит о том, что они значат.
- HTTP-роутеры и очередь — Ф5. Прогон запускается командой, не по API.

## Acceptance (observable)

- [ ] CSV, XLSX и Google Sheet с одинаковым содержимым дают одинаковый результат
- [ ] забракованная строка не роняет приём: она попадает в отчёт с причиной
- [ ] прогон 100 синтетических доменов проходит целиком без сети
- [ ] серии в базе; `RunItem` объясняет судьбу каждого проекта
- [ ] `UnitsLedger` показывает условный расход прогона
- [ ] `pytest` зелёный; сетевых обращений в тестах нет

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| B1 | CSV на 100 строк, 7 из них негодные (пустой `domain`, битый домен, `period_end` раньше `period_start`, нет `client`) | 93 проекта в базе; отчёт: `accepted=93, rejected=7`, у каждой отклонённой — номер строки и причина; исключения нет |
| B2 | тот же список в XLSX и в опубликованной Google Sheet | те же 93 проекта и тот же отчёт, что в B1 — источник не влияет на результат |
| B3 | CSV в cp1251 с кириллицей в `notes` и `client` | текст читается без «кракозябр»; кодировка определена, а не угадана молча |
| B4 | `HTTPS://WWW.Example.com/path?utm=1` · `http://пример.рф` · `example.com.` · `не домен` | `example.com` · `xn--e1afmkfd.xn--p1ai` · `example.com` · брак с причиной `invalid_domain` |
| B5 | повторная загрузка того же файла | проектов по-прежнему 93, не 186; отчёт различает `created` и `updated` |
| B6 | прогон по 100 проектам, `AHREFS_PROVIDER=fixture`, сокет заглушен на уровне теста | прогон завершается `completed`; ни одного сетевого вызова; `MetricPoint` есть по каждому проекту |
| B7 | генератор, сценарий `steady_growth`, `seed=42`, два вызова подряд | серии побайтово совпадают — данные Ф3 воспроизводимы |
| B8 | сценарий `data_hole` | в серии **отсутствуют** месяцы дыры, а не стоят нули: `insufficient_data` в Ф3 обязан отличаться от «трафик упал в ноль» |
| B9 | сценарий `short_history` (4 месяца при периоде работ 18) | прогон принимает проект и помечает `RunItem.note=short_history`; решение о пригодности принимает Ф3, не сбор |
| B10 | прогон шага 1 по 100 проектам | `UnitsLedger`: 100 строк, у каждой `endpoint=metrics-history`, `estimated == actual` (в fixture они совпадают по построению), сумма равна `100 × max(50, Σ стоимость полей select)` |
| B11 | домен, по которому фикстура отдаёт пустую историю | `RunItem.status=skipped`, `reason=no_data`; прогон продолжается и завершается `completed` |
| B12 | `AHREFS_PROVIDER=live` без ключа | ошибка на старте (регрессия A5 из Ф1 — провайдер теперь настоящий, а не заглушка) |

## Non-functional

- Ядро по-прежнему не импортирует FastAPI и RQ (тест изоляции из Ф1 расширяется
  на новые модули автоматически — он обходит пакеты, а не список файлов).
- **Модель стоимости живёт в спеке endpoint'а данными**, в одном месте: fixture
  считает по ней условные units, live в Ф7 сверяет с заголовками
  `x-api-units-cost-*`. Расхождение — наблюдаемая величина Ф7, а не сюрприз.
- В тестах нет сети: fixture-провайдер не ходит наружу по построению, и это
  проверяется заглушенным сокетом, а не доверием.
- Покрытие ядра от 80 % (§10 документа реализации) — с этой поставки цифра
  впервые не пустая.

## Open questions

- **Google Sheet приватной таблицы** требует сервисного аккаунта, которого нет.
  Здесь читаем опубликованную ссылку; приватный доступ — отдельная задача Ф5,
  когда появится место для хранения кредов.
- Формула нормализации на длительность работ — Ф3, не здесь.
- Реальная стоимость запроса в units — Ф7. До неё модель стоимости остаётся
  объявленной гипотезой, и в отчёте прогона так и написано: «условные units».
