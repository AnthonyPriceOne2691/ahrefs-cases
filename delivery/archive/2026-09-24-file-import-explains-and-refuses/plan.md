# Plan: приём файла объясняет, каким он должен быть, и не берёт неподходящий

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L10** — закрытая Google Sheet отвечает страницей входа со статусом 200:
  «ложь успехом вместо ошибки». Та же ложь у файла без колонок: `200` и
  «Принято из …». Лечится тем же приёмом — отказом протокола, а не текстом
  внутри успешного ответа.
- **L64**, **L57** — путь отказа проверяется тестом, иначе человек видит
  пятисотку. Сейчас так и есть: нечитаемая книга (`BadZipFile`) и двоичный CSV
  (`csv.Error`) доходят до `500`. Константа статуса — `HTTP_400_BAD_REQUEST`,
  не устаревшее имя.
- **L67** — сравнивать последствия двух заполнений одного места. Здесь: «нет
  колонки» в шапке — брак файла (отказ целиком), «пусто в ячейке» — брак
  строки (отчёт). Граница проведена по этому различию.
- **L97**, **L101**, **L123** — словарь в компоненте ждёт второго читателя; он
  пришёл (подсказка у файла). Колонки уезжают в данные, общие для обеих
  подсказок, и сверяются с сервером **чтением обоих** (L123): тест берёт
  настоящий JSON фронта и настоящие константы сервера, а не копию списка.
  Почему не справочник с сервера, как у ролей (L101), — в «Rejected».
- **L124** — одно правило соответствия имён. Шапка по-прежнему сличается
  только через `rows.normalize_columns`; «похожее имя» (`Period Start`)
  считается лишь для подсказки и никогда не принимается.
- **L192** — «?» не кладётся внутрь `<label>`: у поля файла подпись и значок
  становятся соседями, поле получает имя через `aria-label`, как у ссылки.
- **L76**, **L77** — попапы Mantine в jsdom медленные: содержимое подсказки
  проверяется данными и в браузере, а не раскрытием карточки в тесте.
- **L186** — подменный сервер сличает метод и самое длинное совпадение пути;
  новые тесты экрана идут через тот же помощник.
- **L68**, **L79** — база общая: «ничего не записано» проверяется по своим
  доменам (префикс), а не счётом всех проектов.
- **L154** — не применим: `--only` читает колонку `domain` из того же файла и
  правкой не задет.
- **L8**, **L58**, **L73** — «зелёный по причине окружения». Дев-база общая с
  тремя параллельными ветками, поэтому pytest целиком гоняется на своей чистой
  базе, которую сьют сам поднимает миграциями, как в CI; «ничего не записано»
  считается по своему префиксу (`_own_projects`), а не по всей базе.
- **L132**, **L170** — починив один вызов, проверь остальные; признак без
  потребителя — надпись. `UnfitSourceError` ловят все три потребителя приёма:
  файл и ссылка в роутере, `_intake` в CLI — у каждого свой тест (V1–V15,
  V21); поле `RawTable.where` читает `check_fit`.
- **L166** — CLI гоняется подпроцессом, и его покрытие считается через тот же
  помощник `_run`: новый тест V21 идёт им же.
- **L204** — сверяется собранное: проверка в браузере идёт на боевой сборке
  (`vite build`) ветки и `origin/main`, а не на dev-сервере.
- **L50**, **L111**, **L138**, **L142**, **L145**, **L150** — не применимы:
  `_intake` вырос на шесть строк (файл далёк от 500), приём не платит и не
  выбирает источник рядов, ключ проекта при записи не менялся.

## Approach

1. **Граница в одном месте.** `validate.check_fit(table)` — первым шагом
   `validate_table`: нет ни одной строки, колонка из известных дважды, нет
   обязательных колонок, только шапка. Каждый случай — `UnfitSourceError`
   (новый тип рядом с кодами отказа, `rejections.py`) с текстом: что не так,
   что прочитано, какие колонки ожидаются. Имена собираются из
   `REQUIRED_COLUMNS`/`OPTIONAL_COLUMNS`. Коды строк `empty_source` и
   `missing_column` уходят вместе с переводами на экране — сервер их больше не
   шлёт.
2. **Читатели не роняют сервер.** `xlsx_source`: любая ошибка openpyxl на
   чтении книги — `UnfitSourceError` «не читается как книга Excel»; читатель
   записывает, какой лист прочитан и какие ещё есть (`RawTable.where`).
   `csv_source`: `csv.Error` — отказ; нулевой байт в начале текста — «не похож
   на текст». `gsheet_source`: `where` называет лист из ссылки (gid).
3. **Роутер.** Оба пути ловят `UnfitSourceError` → `400` с подлежащим («Файл
   «x» не подходит: …», «Таблица по ссылке не подходит: …») и структурным
   логом `intake_refused`. Пустое тело — «файл пуст».
4. **CLI.** `_intake`: неподходящий список — код 2 и «список не подходит: …».
5. **Экран.** `listFormat.json` — единственный список колонок с примерами,
   необязательные, форматы файла и предел. `ListHelp.tsx` — одна карточка на
   обе подсказки (`SheetHelp`, `FileHelp` различаются первым абзацем).
   `SourceForm`: подпись и «?» соседями у обоих полей; отказ — под полем,
   которым давали список; `accept` берётся из данных; после каждого выбора
   файла поле выбора сбрасывается (`resetRef`), иначе тот же файл второй раз
   не выбирается.
6. **Реляционный оракул.** pytest читает `listFormat.json` и сравнивает с
   `REQUIRED_COLUMNS`, `OPTIONAL_COLUMNS`, `MAY_BE_EMPTY`, `FILE_SUFFIXES` и
   `MAX_UPLOAD_BYTES`.

## Rejected alternatives

- **Эндпоинт `GET /api/intake/columns` для подсказки** — отклонён, потому что
  с сервера пришли бы только имена, а описания и примеры остались бы на фронте:
  проверка «описано то, что требуется» нужна всё равно. Сверх неё эндпоинт
  добавляет подсказке состояние загрузки и отказа, а каждому тесту экрана —
  ещё один подменный ответ. Роли (L101) меняются в базе на ходу; колонки —
  константы кода, сервер и фронт уезжают одним коммитом, и сверки при сборке
  достаточно.
- **Оставить брак файла в отчёте, поменять заголовок экрана** — отклонён,
  потому что `200` говорит «принято» всем потребителям сразу: CLI возвращает 1
  вместо 2, лог пишет `intake_accepted`, а экрану пришлось бы разбирать
  содержимое отчёта, чтобы понять, был ли успех. Отказ — дело протокола.
- **`422` вместо `400`** — отклонён, потому что у FastAPI `422` — ответ
  валидации запроса со списком в `detail`, который экран не читает
  (`readDetail` берёт только строку), а остальные отказы приёма уже `400`.
- **Молча принимать `Period Start` как `period_start`** — отклонён, потому что
  это расширение формата, а владелец просил не брать неподходящее; вместо
  этого отказ подсказывает ближайшее верное имя.
- **Проверка на клиенте до отправки** — отклонена, потому что это вторая копия
  правил сервера, а сервер отвечает текстом за миллисекунды. Исключение —
  размер, и оно найдено исполнением (converge, V22): ответ `413` через прокси
  до человека не доходит, а предел берётся из данных, сверенных с сервером.

## Risks

- Тесты, сеющие проекты через `accept()` с неполной шапкой, начнут падать —
  прогон целиком обязателен.
- Подсказка «похожего имени» может ошибиться — она только текст, приём по ней
  ничего не делает.
- Длинный текст отказа на экране — плашка переносит строки; проверяется в
  браузере.

## Rollout / migration

Миграций нет. Выкатка обычная (`docs/PROD.md`).

## Test / eval strategy

- pytest: отказы API по каждому примеру V1–V15, `400` и «ничего не записано»;
  тексты `check_fit`; реляционный оракул данных подсказки; код CLI (V21).
- vitest: V16–V18, V20 (сброс поля выбора после ответа).
- Браузер (боевая сборка, копия дев-базы): обе подсказки в тёмной и светлой
  теме, отказы у своих полей, повторный выбор того же файла, ссылка через
  подменённый транспорт. `eval-smoke.md`.
