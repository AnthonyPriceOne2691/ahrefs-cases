# Spec: карточка проекта — вердикт, А → Б, кривые

## Problem

Группа проекта видна в таблице, а откуда она взялась — нет. Вердикт с условиями
и точками записан в базе с Ф3, отдаётся по HTTP с Ф5, рисунок готов с прошлой
поставки — и всё это упирается в заглушку на `/projects/:id`.

Без экрана «почему» сотрудник либо верит числу на слово, либо идёт к инженеру.
Оба варианта плохи там, где решают, показывать ли проект клиенту.

## In scope

- Экран `/projects/:id`: шапка с доменом, нишей, гео, периодом и группой.
- **Главный результат крупно** — рост органического трафика, как в кейсе.
- **Таблица А → Б**: метрика, было, стало, рост. Подписи метрик и арифметика
  роста приходят **с сервера**: они уже существуют в кейсе, и второй экземпляр
  разошёлся бы с первым.
- **Объяснение группы**: условия вердикта с фактом, порогом и пометкой
  решающего — то, чего в кейсе нет вовсе.
- Графики из `GET /api/projects/{id}/charts` — те же, что в PDF.
- Версия порогов и время решения: вердикт принадлежит версии, и без неё число
  ничего не значит.
- Состояния: грузится, нет вердикта, проекта нет (`404`), отказ по праву.

## Out of scope

- **Тумблер «месяц/квартал/год»** — отдельной поставкой: рисунок строится на
  сервере, значит переключателю нужен параметр эндпоинта и агрегация перед
  рисованием, а не кнопка на фронте.
- Пересчёт и предпросмотр порогов с этого экрана: у них свой раздел.
- Скачивание PDF проекта: это раздел «Кейсы».
- Диагностика «плохих» (Ф3в) отдельным блоком: она существует в CLI, и её место
  на экране — решение, которого пока не принимали.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | проект с вердиктом | домен, группа, счёт, версия порогов на экране |
| E2 | тот же проект | таблица А → Б с подписями метрик и ростом |
| E3 | тот же проект | условия вердикта: факт, порог, решающее отмечено |
| E4 | тот же проект | два графика с заголовками |
| E5 | проект без вердикта | «не классифицирован» и объяснение, что делать |
| E6 | проект без рядов | карточка есть, блок графиков пуст |
| E7 | несуществующий проект | «проекта нет», а не пустой экран |
| E8 | сервер ответил отказом | текст сервера |
| E9 | клик «к списку» | возврат на `/projects` |
| E10 | числа таблицы А → Б | совпадают с числами вердикта из API |

## Non-functional

- Подписи метрик — один словарь на кейс и карточку (серверный).
- Рост считается одной функцией с классификацией: карточка не пересчитывает.
- Узкий экран: таблица прокручивается, графики сжимаются.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- Сноска на карточке короче кейсовой: кейс уходит клиенту и несёт полную
  формулировку про оценки Ahrefs, карточка — внутренний экран. Если окажется,
  что карточку показывают клиенту, текст надо будет сравнять.
