# Spec: действующая версия порогов — ровно одна, и тесты её не уносят

## Problem

Две беды одного корня: **флаг `is_active` у версии порогов меняют кто угодно и
как угодно**.

1. Тесты (`test_api_read`, `test_api_charts`, `test_api_thresholds`) ставили
   `ruleset.is_active = True` своей версии, не гася чужую. На общем стенде это
   означало: после прогона активна не та версия, что была до него. Стоило часа
   разбирательства — пересчёт «по действующей» считал не то.
2. Оттуда же состояние «две активные версии». `active_ruleset` берёт новейшую
   по id и молчит; вердикты считаются версией, которую никто не утверждал.
   Восемь тестов карточки при этом падали `TypeError` — по причине окружения,
   а не кода: их вердикт привязан к их версии, а действующей была чужая.

## In scope

- Частичный уникальный индекс `uq_ruleset_single_active`: две активные версии
  становятся невозможны, а не маловероятны. Миграция гасит лишние перед
  созданием индекса.
- `recalc.activate` переключает версию в явном порядке: погасить все → зажечь
  одну. Индекс проверяется на каждом statement'е и отложенным быть не может.
- Общие помощники в `tests/owned_rows.py`: запомнить действующую версию,
  сделать свою действующей, вернуть стенду его.

## Out of scope

- Изоляция тестов отдельной базой: решение Ф1 «общая база» остаётся, поставка
  достраивает правило уборки до случая «чужой флаг».

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | попытка сделать активными две версии | отказ базы, а не тихое состояние |
| E2 | активация версии на базе, где активная уже есть | проходит: порядок явный |
| E3 | прогон тестов на стенде с активной `0.1.0` | после прогона активна `0.1.0` |
| E4 | тест карточки на стенде с чужой активной версией | зелёный: тест делает свою версию действующей |
| E5 | миграция на базе с двумя активными | лишние гаснут, индекс создаётся |

## Non-functional

- Продукт не меняет поведения: переключение версии делает то же самое, просто
  в определённом порядке.
