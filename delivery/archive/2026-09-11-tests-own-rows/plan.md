# Plan

Класс M. Общая уборка по владению, правка четырёх модулей, оракул.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L79** — свой, вчерашний: `delete(Model)` без фильтра стирает чужое.
- **L8** — дев-база живёт между прогонами; изоляция даётся откатом, а не
  уничтожением.
- **L68** — инвариант, держащийся на всей базе, не изолируется откатом: API
  ходит своими соединениями, поэтому уборка нужна и она обязана быть точной.
- **L58** — «зелёный по причине окружения»: тест после такой уборки зелен,
  потому что убрал за собой; увидеть беду можно только по чужим данным.

Не применимы: **L53**, **L74** — выбора источника поставка не трогает.

## Шаги

1. `tests/owned_rows.py` — `delete_owned(session, domains=…, emails=…)`:
   проекты по домену → их вердикты, точки, кейсы и артефакты; прогоны по
   своему пользователю → их строки расхода.
2. `tests/test_api_read.py`, `test_api_runs.py`, `test_api_intake.py`,
   `test_api_thresholds.py` — уборка через общий помощник.
3. `tests/test_cleanup_scope.py` — оракул: разбор AST файлов `tests/`, поиск
   `delete(...)` без `.where`, выход пометкой с причиной.
4. Проверка исполнением: контрольные строки до и после полного прогона.

## Rejected alternatives

- **Отдельная база под тесты** — отклонено, потому что дев-база общая нарочно:
  на ней смотрят экраны и готовят показ, а контейнер на прогон стоил бы
  времени каждому запуску.
- **Грепом в pre-commit вместо теста** — отклонено, потому что правило про
  тесты, и жить ему там же, где тесты: оракул-тест не требует правки канонных
  скриптов и сам попадает в CI.
- **Удалять по «всё, что создано после начала теста»** — отклонено: метки
  времени у строк разные, а часть создаётся приложением в своей транзакции;
  владение выражается связью, а не временем.
- **Оставить как есть и не запускать тесты на дев-базе** — отклонено: тесты
  требуют базы (это решено поставкой `tests-need-db`), а второй базы нет.
