# Spec: заведение людей и правка прав

## Problem

Учётки заводятся только курлом. Администратор — руководитель, а не инженер, и
каждое «заведи человека» сейчас идёт через того, у кого есть консоль.

Права при этом двухслойны, и правка личного права — это ровно то действие,
ради которого слой заведён: «этому можно править пороги, хотя он в группе
пользователей», «этому — нельзя, хотя он админ».

## In scope

- Заведение человека: почта, имя, группа. Пароль генерирует сервер.
- **Пароль показывается один раз**, крупно и с прямым предупреждением: второго
  показа не будет, повторно — только перевыпуск.
- Правка выбранного человека: группа, доступ ко входу, личные права.
- Личное право — три состояния: «как в группе», «выдать», «отобрать».
  Третье существует потому, что группа право даёт, а человеку оно не нужно.
- Перевыпуск пароля — с тем же показом один раз.
- Отказы сервера показываются его словами: занятая почта (`409`), последний
  администратор (`409`), выключение себя (`409`), неизвестное право (`422`).

## Out of scope

- Удаление людей: в API нет намеренно — за учёткой тянутся прогоны и расход.
- Смена своего пароля: это отдельный сценарий (`/api/auth/password`) и место
  ему в профиле, а не в управлении людьми.
- Приглашения по почте: почтового канала у сервиса нет вовсе.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | завели человека | строка появилась, пароль показан один раз |
| E2 | почта занята | `409` словами сервера, список не изменился |
| E3 | сменили группу | новая группа в строке, права пересчитаны |
| E4 | выдали право лично | помечено «выдано лично» |
| E5 | отобрали право группы | помечено «отобрано лично» |
| E6 | сняли группу с последнего админа | `409` словами сервера |
| E7 | перевыпустили пароль | новый пароль показан один раз |
| E8 | закрыли вход | учётка помечена «вход закрыт» |
| E9 | пароль показан и панель закрыта | пароля больше нет на экране |

## Non-functional

- Пароль не попадает ни в адресную строку, ни в `localStorage`: он живёт в
  состоянии экрана и исчезает вместе с панелью.
- Список перезапрашивается после каждой правки: он и есть подтверждение, что
  сервер согласился.
- Узкий экран: форма в одну колонку.
- Поставка укладывается в `max_loc_diff` 800 без waiver.
