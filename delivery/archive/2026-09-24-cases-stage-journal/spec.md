# Spec: журнал сборки кейсов говорит правду

## Problem

Ступень кейсов — кнопка «Собрать кейсы» (`POST /api/runs/cases`, задача
`cases_job` в `workers/jobs.py`) — пишет в журнал прогона неправду. Живой прогон
на проде 24.09.2026: журнал — «собрано 0 из 53, пропущено 53», раскрытие по «?»
— «записей по доменам нет: прогон не дошёл до сбора». Лог воркера в то же время
печатает верную сводку: «кейс собран: 10, не положен по группе: 41, данных не
хватило: 2, вердикт не про эти данные: 0; архив …; кейсов внутри: 10». Знание
есть, в журнал не доходит (урок L130): задача зовёт `pack_cases`, который
отдаёт только код возврата, строк судеб не пишет никто, а «пропущено» журнал
вычитает из числа проектов, записанного при постановке в очередь.

Рядом то же в оповещениях: «готов кейс <файл> — проверьте перед публикацией»
(`api/routers/alerts._ready_bundle`) называет самый свежий артефакт кейса, хотя
докстрока обещает пачку. На копии дев-базы оповещение говорило «готов кейс
wineverygame.com — Кейс v43.pdf» после сборки, которая не положила в каталог
выгрузки ни одного файла, и «готов кейс zooplus.de — Кейс v11.pdf» после
пачки из 61 кейса.

## Users / stakeholders

Владелец и сотрудники агентства: по журналу они решают, чем кончилась сборка и
что делать дальше; по оповещению — пора ли открывать пачку перед публикацией.

## In scope

- Счётчики прогона ступени кейсов — по фактической сборке: «собрано» — кейсы,
  лёгшие в пачку; «из N» — рассмотренные проекты; остальное — пропущено.
- Судьба каждого рассмотренного проекта строкой журнала, исход словами:
  «собран», «не положен по группе», «данных не хватило», «вердикта этой версии
  нет», «вердикт не про эти данные», «не отдан: контент-запрет» — с причиной.
- У «вердикт не про эти данные» совет, который не вредит проду:
  переклассифицировать по тем рядам, по которым вынесен вердикт, а не по
  текущему режиму провайдера. Тот же текст печатает команда `cases`/`pack`.
- Раскрытие прогона показывает строками то, что требует действия; «не положен
  по группе» — числом, как «собран»: это воронка, а не беда (урок L214).
- Оповещение о готовой пачке говорит про пачку — её имя и число кейсов в ней;
  пачку, которую не отдают (в ней кейс удалённого проекта), готовой не
  называет.
- Строки ступени кейсов не ломают память о пустом домене (`cache.empty_since`,
  Z33): Ahrefs эта ступень не спрашивает, и её исходы — не проверки домена.

## Out of scope

- Домен в журнале по-человечески и режим прогона — соседняя поставка
  «мелочи журнала» (PR #26).
- Журнал шага 2 и «данных под кейс» — пишутся сбором, как прежде.
- Доставка оповещений в каналы (Telegram, Asana) — не делалась и не делается.

## Acceptance (observable)

- [ ] Журнал прогона сборки кейсов показывает собранные кейсы числом и каждый
      проект — судьбой со словами и причиной.
- [ ] Совет у «вердикт не про эти данные» называет ряды вердикта.
- [ ] Оповещение называет пачку и число кейсов в ней.

## Acceptance examples

Сборка кейсов — кнопкой, через `POST /api/runs/cases` и очередь; провайдер
`fixture`, вердикты — своей версии порогов. Свои проекты:
`journal-good.example` (хороший, ряды фикстурные), `journal-poor.example`
(плохой), `journal-thin.example` (данных не хватает), `journal-live.example`
(хороший, вердикт по живым рядам), `journal-blocked.example` (хороший, гео
`BY`), `journal-new.example` (вердикта этой версии нет).

| # | Вход | Ожидаемый выход |
|---|---|---|
| Y1 | Сборка кейсов по своим проектам | `GET /api/runs/{id}`: статус `done`, `projects_ok` 1, `projects_total` — число судеб, `projects_skipped` — `projects_total − 1`; судьбы своих проектов: `ok` у good, `case_not_eligible` у poor, `case_insufficient_data` у thin, `case_verdict_mismatch` у live, `case_blocked` у blocked, `case_no_verdict` у new. До правки: `projects_ok` 0, судеб нет |
| Y2 | То же — причины | good — «кейс собран: journal-good.example — Кейс v1.pdf»; poor — «группа «плохой»: кейс по ТЗ собирают хорошим и средним»; thin — про группу «данных не хватает» и карточку проекта; blocked — «контент-запрет: гео: «BY»»; new — называет действующую версию порогов |
| Y3 | Вердикт `journal-live.example` вынесен по живым рядам, сборка читает фикстурные | причина: «вердикт вынесен по рядам «live», а показаны «fixture» — переклассифицируйте по рядам «live», по которым вынесен вердикт (`classify --source live`), а не по текущему режиму»; `--source fixture` в ней нет |
| Y4 | Вердикт по фикстурным рядам, ряд докуплен в окно после вердикта (числа не воспроизводятся) | совет — `classify --source fixture`: ряды вердикта и ряды сборки тут одни |
| Y5 | Пустой домен: два сбора подряд «нет данных», потом сборка кейсов записала ему «вердикта этой версии нет» | `cache.empty_since` по-прежнему отдаёт время последней настоящей проверки; следующий сбор берёт пустоту из памяти и не покупает её |
| Y6 | Экран: у прогона сборки кейсов судьбы — 10 `ok`, 41 `case_not_eligible`, 2 `case_insufficient_data`, по одной `case_verdict_mismatch` и `case_blocked` | в раскрытии строки только у «данных не хватило» (две), «вердикт не про эти данные» и «не отдан: контент-запрет» — с причинами; «без замечаний собрано: 10» и «не положен по группе: 41» — по строке числом; строк с доменами «не положен по группе» нет |
| Y7 | В каталоге выгрузки пачка сборки из Y1 (один кейс) | `GET /api/alerts`: повод `cases_ready` — «готова пачка кейсов «кейсы-<дата>.zip»: кейсов внутри — 1 — проверьте перед публикацией»; имени отдельного PDF в нём нет |
| Y8 | Пачки в каталоге выгрузки нет, артефакты кейсов в базе есть | повода `cases_ready` нет. До правки: «готов кейс <свежий PDF>» |
| Y9 | В пачке PDF, чьей суммы нет ни у одного артефакта (кейс удалённого проекта) | повод `cases_pack_blocked`, степень `warning`: «пачка кейсов «…» не отдаётся: в пачке кейс удалённого проекта — пересоберите кейсы, и архив соберётся без него»; `cases_ready` нет |
| Y10 | Копия дев-базы: сборка кнопкой (API + воркер RQ) — с живыми вердиктами как есть и после переклассификации по фикстурным рядам | журнал через API и экран в Chrome: «N из 75», где N — число PDF в пачке; судьбы по исходам совпадают с отчётом сборки; оповещение называет пачку и N. До правки: «0 из 75, пропущено 75», судеб нет, оповещение — про отдельный PDF |

## Non-functional

- Ни одного запроса к Ahrefs: ступень кейсов читает купленное.
- Миграция добавляет значения перечисления исходов (`ALTER TYPE … ADD VALUE`) и
  ничего не переписывает; откат кода её не требует.
- Сводка сборки по-прежнему печатается в лог воркера.

## Open questions

- Если вердикт вынесен по одним рядам, а сборка читает другие (режим провайдера
  сменили после классификации), совет «переклассифицируйте по рядам вердикта»
  кейс не соберёт: сборка читает ряды режима. Собрать кейс по рядам вердикта
  или переписать вердикт рядами режима — решение владельца; совет выбран тот,
  что не переписывает вердикты ни в каком режиме.
