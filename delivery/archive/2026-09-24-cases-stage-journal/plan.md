# Plan: cases-stage-journal

Класс M, bugfix. Задача сборки кейсов получает от сборки не код возврата, а
исходы по проектам, пишет их строками журнала и закрывает прогон тем же
`finish_run`, что сбор. Исходы ступени кейсов — новые значения перечисления
исходов прогона; память о пустом домене их не считает. Совет у «вердикт не про
эти данные» называет ряды вердикта. Оповещение читает пачку, а не артефакты.

Поставка опирается на #27 (слит в `main` 24.09.2026, 1a4a785): судьбы собранных
кейсов берутся из исходов `pack` по номеру проекта, которые вводит она.

## Шаги

1. **Красные тесты первыми.** `tests/test_cases_journal.py`: Y1–Y3, Y7–Y9
   через API; Y4 — в `tests/test_cases_builder.py`; Y5 — в
   `tests/test_collect_run.py`; Y6 — в `web/src/pages/__tests__/ops.test.tsx`.
   Y1 (repro) падает на ветке-основе тем, что `projects_ok` 0 и судеб нет.
2. **Исходы.** `storage/_enums.py`: `CASE_NOT_ELIGIBLE`, `CASE_INSUFFICIENT_DATA`,
   `CASE_NO_VERDICT`, `CASE_VERDICT_MISMATCH`, `CASE_BLOCKED` и множество
   `CASE_OUTCOMES`; миграция `ALTER TYPE run_item_outcome ADD VALUE` на пять
   имён; `collect/cache.empty_since` их не считает.
3. **Сборка отдаёт исходы.** `cli/case_commands.py`: `pack_built` — сборка,
   пачка и запись одним вызовом в сессии вызывающего, результат `CasePack`;
   `case_fates` — судьба каждого проекта словами. `pack_cases` печатает из
   того же результата. `export/archive.py`: `EmptyArchiveError` несёт
   запрещённые кейсы — пустая пачка не теряет, кому отказано.
4. **Задача.** `workers/jobs._pack` пишет судьбы (`add_item`), число
   рассмотренных проектов и закрывает прогон `finish_run`; сводку — в лог.
5. **Совет.** `cases/builder._mismatch` — ряды вердикта; `project_id` у каждой
   попытки.
6. **Оповещение.** `api/routers/alerts._ready_bundle` — свежая пачка из
   каталога выгрузки, число PDF в ней (`archive.cases_inside`); пачка с кейсом
   удалённого проекта — `cases_pack_blocked`.
7. **Экран.** `web/src/pages/status.ts` — слова исходов; `RunFates.tsx` —
   «не положен по группе» числом.
8. **Канон.** `knowledge/product/case-content.md` (правила 3, 3а, 19),
   `knowledge/engineering/collection/data-coverage.md` (память о пустом
   домене), `knowledge/log.md`.
9. **Исполнение.** Копия дев-базы, API + воркер RQ (`SimpleWorker`), кнопка
   через API в двух состояниях копии; журнал через API и экран в headless

10. **Handoff.** verify-report, метрики, `docs/FINDINGS.md` (Z46), архив,

## Rejected alternatives

- **Сопоставить исходы старыми значениями** (`ok`, `skipped_no_data`,
  `skipped_invalid`) без миграции — отклонено, потому что слово исхода на
  экране берётся из значения, и «не положен по группе» читалось бы «пропущен:
  строка не принята»; расшифровка по ступени прогона была бы вторым словарём
  поверх первого.
- **Хранить судьбы ступени кейсов в `Run.params_snapshot`** — отклонено,
  потому что снимок — параметры прогона, а не его итоги, и журнал читал бы
  судьбы из двух мест в зависимости от ступени; `run_items` уже дают свёртку,
  пометку «проект удалён» и потолок выдачи.
- **Отличать ступень кейсов в `empty_since` по `params_snapshot["stage"]`** —
  отклонено, потому что `collect/cache.py` не может импортировать константу
  ступени из `run_journal` (цикл `cache → run_journal → fetch → plan → cache`),
  а вторая копия строки `"cases"` разошлась бы с первой; множество исходов
  живёт в перечислении, где его видят оба.
- **Совет «переклассифицируйте по текущему режиму»** (как было: «по этому
  источнику») — отклонено по слову координатора, потому что на проде в
  `fixture` такой пересчёт переписал бы живые вердикты фикстурными; пересчёт
  по рядам вердикта не переписывает ничего ни в каком режиме.
- **Оставить «не положен по группе» строками в раскрытии** — отклонено, потому
  что на проде это 41 строка из 53, ровно тот случай, из-за которого собранные
  свернули в число (L214).

## Risks

- Миграция на проде идёт сама перед `api` (`docker compose up`, сервис
  `migrate`); `ADD VALUE IF NOT EXISTS` не переписывает строк, бэкап — по
  `docs/PROD.md` перед обновлением.
- Судьбы ступени кейсов — новые строки `run_items` у каждого проекта при каждой
  сборке: предпросмотр удаления («строк журнала прогонов: N») вырастет на число
  сборок. Это правда журнала, а не шум.
- Две поставки держат в работе один экран (`status.ts`): правки в разных местах
  файла, слияние — обычным merge.
