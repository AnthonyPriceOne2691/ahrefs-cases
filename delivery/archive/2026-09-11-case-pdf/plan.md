# Plan

Класс M. Шаблон, два рендерера, стоп-лист и команда CLI.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L41** (`cases/`) — кейс показывает числа вердикта; рендер их только
  форматирует. Формат обязан менять вид, а не значение — отсюда пример E8.
- **L30** (`classify/coverage.py`) — «не покупали» и «нет» различаются: метрики,
  которой нет в структуре, в PDF нет вовсе, а не пустой строкой таблицы.
- **L23** (`collect/provider.py`) — умолчание стирает разницу между «не смогли
  проверить» и «проверили, чисто». Стоп-лист обязан падать, а не пропускать
  (E6).
- **L1** (`backend/features/robots/`) — тот же класс из другого проекта: пустой
  ответ и недоступный ответ слиты в один случай. Здесь это «текста нет» против
  «текст не разобрали».
- **L21** (`tests/`) — тест не должен стоять на файле, которого нет в
  репозитории: шаблон лежит в `templates/` и коммитится, а не берётся из
  клиентских документов.
- **L24** — перенося чужой паттерн, переноси опору: печатные приёмы (@page,
  `break-inside: avoid`, margin-boxes) взяты из документации WeasyPrint и
  печатного CSS, а не из вёрстки для экрана.

Не применимы: **L27**, **L37**, **L22**, **L40** — покупок в поставке нет.
**L3** (`.git/info/exclude` действует только на неотслеживаемые пути) сработал
прямо здесь: `src/ahrefs_cases.egg-info/` был закоммичен раньше и менялся при
каждой установке — выведен из индекса `git rm --cached`, а не только внесён в
`.gitignore`. `extract_payload.py --check-local .` даёт оба нуля.

## Шаги

1. `pyproject.toml` — `jinja2` и `weasyprint` в обязательные зависимости.
2. `.importlinter` — `export` встаёт над `cases`: рендер знает структуру.
3. `cases/stoplist.py` — правила запрета, проверка текста и гео, fail-closed.
4. `templates/case.html.j2` — макет A4: шапка, главный результат, три плитки,
   таблица А → Б, сноска и атрибуция, пустой блок под графики.
5. `export/html_renderer.py` — окружение Jinja2 с автоэкранированием, форматтеры
   чисел, `CaseData` → HTML.
6. `export/pdf_renderer.py` — WeasyPrint, запись файла, вызов стоп-листа перед
   выдачей.
7. `scripts/run_collect.py` — команда `render <домен>`.
8. `tests/test_cases_pdf.py` — E1–E10.

## Rejected alternatives

- **Рисовать заглушку «здесь будет график»** — отклонено, потому что артефакт
  уходит клиенту: пустая рамка с обещанием хуже её отсутствия. Блок шаблона
  пуст и заполнится поставкой 4.
- **Считать «какие три метрики в плитках» правилом подсветки** — отклонено,
  потому что правило подачи едет вместе с текстом: здесь плитки берут первые
  три изменения по фиксированному порядку, и это видно в шаблоне.
- **Веб-шрифты ради вида** — отклонено, потому что сервер агентства может быть
  без выхода в интернет, а кейс обязан собираться: системный sans и никакой
  сети при рендере.
- **Проверять стоп-лист после рендера, по готовому PDF** — отклонено, потому
  что разбор PDF обратно в текст — лишний шаг с потерями; проверка идёт по
  структуре и HTML, до записи файла.
- **Пропускать кейс, если стоп-лист не смог разобрать текст** — отклонено,
  потому что «проверка не отработала» и «проверка пройдена» — разные вещи, а
  цена ошибки здесь публикация запрещённого упоминания.
