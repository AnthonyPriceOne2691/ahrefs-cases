# Spec: три хвоста живого прогона

## Problem

Прогон Ф7 12.09.2026 нашёл три вещи, которых не видит ни один из 474 тестов,
потому что все три проявляются только на исполнении.

1. **Остаток квоты считается по ключу**, а лимитов два: ключа и воркспейса.
   Воркспейс общий с другими сервисами агентства.
2. **`collect` собирает всю базу.** На стенде рядом с боевым списком лежат
   отладочные проекты — прогон ушёл в Ahrefs и за ними.
3. **Подпись последнего значения на кривой обрезана** границей `viewBox`.
   Это артефакт, который уходит клиенту.

## In scope

- Остаток = `min(остаток ключа, остаток воркспейса)`; отсутствие полей
  воркспейса — «второго потолка нет», а не «остаток неизвестен».
- `collect --only`: домены через запятую или файл со списком; названный домен,
  которого нет в базе, останавливает прогон.
- Подпись значения выбирает сторону: справа, если влезает, иначе слева.

## Out of scope

- Ограничение живого режима «только по списку» насильно: решение о составе
  прогона остаётся за человеком, а не за флагом по умолчанию.
- Перенос того же выбора стороны на подпись «старт работ»: она стоит у начала
  периода, и там места хватает. Вернётся вопросом, если период начнётся справа.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | ключ 1 469 188, воркспейс 100 000 | остаток 100 000 |
| E2 | в ответе нет полей воркспейса | остаток по ключу, без ошибки |
| E3 | `--only d1,d3` при трёх проектах | собраны ровно два, ряды только у них |
| E4 | `--only` с неизвестным доменом | прогон останавливается с именем домена |
| E5 | семизначное последнее значение | подпись развёрнута влево и внутри рамки |
| E6 | трёхзначное последнее значение | подпись справа от точки |

## Non-functional

- Ширина знака считается с запасом: ошибиться в сторону «не влезет» дешевле.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- `--only` не спрашивает подтверждения, когда список пуст и берётся вся база.
  Подтверждение имеет смысл добавлять вместе с боевым ключом, а не раньше.
