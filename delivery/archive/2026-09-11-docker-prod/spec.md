# Spec: боевой образ и компоуз

## Problem

Дев-окружение в контейнерах есть, боевого нет. Разница не косметическая: в бою
фронт — это собранные файлы, отданные nginx, а не vite с исходниками; исходники
не монтируются; секреты приходят из окружения сервера, а не лежат в файле
рядом с компоузом; API запускается без `--reload`.

Ф9 («сервис живёт на сервере агентства») начнётся с того, что этот путь
попросят. Собранный впервые на сервере, он превращает «залью на сервер» в
неделю отладки — ровно то, от чего план предостерегает отдельным абзацем.

## In scope

- Стадии образа: `web-build` (сборка фронта) и `web` (nginx + собранные файлы).
- `nginx.conf`: статика, `/api` в бэкенд, `try_files` для маршрутов SPA.
- `docker-compose.yml` (боевой): postgres, redis, migrate, api, worker, web.
  Без монтирования исходников, без `--reload`, с рестартом `unless-stopped`.
- Секреты — **только** из окружения сервера: `.env.example` называет их, файл
  компоуза значений не содержит.
- `.env.example` пополняется тем, что нужно боевому запуску.
- Проверка исполнением: собрать, поднять, открыть экран и войти **через nginx**.

## Out of scope

- TLS, домен и выпуск сертификата — на сервере (Ф9): здесь nginx слушает
  обычный порт, а TLS ставится перед ним там, где есть домен.
- Публикация образов в реестр и CI-деплой: пока собираем на сервере из
  исходников; реестр появится, если сборка на сервере окажется дорогой.
- Бэкапы, мониторинг, уведомления — Ф9.
- Ограничения ресурсов контейнеров: подбираются на сервере под его железо.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | `docker compose build` | собираются боевые образы, включая статику фронта |
| E2 | `docker compose up -d` | поднимаются шесть сервисов, migrate завершается до api |
| E3 | `curl :8080/` | HTML приложения, отданный nginx |
| E4 | `curl :8080/api/health` | ответ бэкенда через прокси nginx |
| E5 | вход через `:8080` | токен возвращается: путь `nginx → api` живой |
| E6 | открыть `:8080/intake` напрямую | экран, а не 404 (маршрут SPA отдаёт `index.html`) |
| E7 | `JWT_SECRET` не задан | сервис не поднимается молча — причина названа |
| E8 | боевой образ | внутри нет ни `.venv`, ни исходников фронта, ни dev-зависимостей |
| E9 | контейнер убит | поднимается сам (`restart: unless-stopped`) |

## Non-functional

- Один `Dockerfile` на оба режима: дев и прод отличаются стадией, а не файлом.
  Иначе дев перестаёт проверять прод.
- В файле компоуза нет ни одного значения секрета — только имена переменных.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- Порт 8080 выбран, чтобы не спорить с занятым 80 на машине разработчика. На
  сервере он станет 80/443 — это правка одной строки и решение Ф9.
