# Tasks: journal-shows-only-trouble

## Mini-spec

**Проблема.** «?» у «пропущено N» в журнале прогонов раскрывает судьбы всех
проектов прогона. У прогона №2 прода это 53 строки, из них 51 «собран — вся
история уже собрана», и две настоящие причины тонут среди них. Докстринг
компонента обещает другое: «кого прогон не собрал и почему».

**Примеры приёмки.**

- **J1.** Прогон с исходами `ok` и проблемными: в раскрытии только
  проблемные (`skipped_*`, `failed`), строк «собран» нет; под ними одна строка
  «без замечаний собрано: N».
- **J2.** Две кампании одного сайта с проблемой в одном прогоне — обе строки
  видны (ключ строки не домен: у двух кампаний он одинаков).
- **J3.** Все исходы `ok` (знак «?» бывает и у упавшего прогона с причиной):
  таблицы нет, одна строка «без замечаний собрано: N».
- **J4.** Прежнее не сломано: упавший прогон по-прежнему показывает причину
  отказа (тест трассировки), прогон без записей — «записей по доменам нет».

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L130** — «пишется в базу» и «видно человеку» — разные стадии готовности.
  Здесь обратное: видно слишком много, и главное (почему пропущены) тонет.
  Судьбы по-прежнему приходят все: фильтр — решение экрана, а не API.
- **L13** — исход сворачивается по проекту; две кампании одного сайта — два
  проекта, и две строки обязаны остаться двумя (J2).
- **L185**, **L184** — раскрытие живёт отдельной строкой во всю ширину;
  правка его внутренность не трогает.
