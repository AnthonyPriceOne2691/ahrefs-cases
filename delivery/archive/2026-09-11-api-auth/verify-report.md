## Ревью рисковых мест

**Это первая поставка, где ошибка открывает дверь.** Три решения приняты в
пользу закрытости: одинаковый ответ на неизвестную почту и неверный пароль
(и одинаковое **время** ответа — хеш проверяется даже у ненайденного), пустой
секрет не выпускает токенов вовсе, а пользователь перечитывается из базы на
каждый запрос, чтобы выключенный сотрудник терял доступ сразу.

**Цена последнего решения названа:** лишний `SELECT` на каждый защищённый
вызов. Альтернатива — верить группе из токена — дала бы до 12 часов, в которые
уволенный сотрудник продолжает работать.

**Безопасность.** Пароль не попадает ни в лог, ни в ответ, ни в сообщение об
ошибке. Хранится bcrypt-хешем с солью на каждый пароль; испорченный хеш в базе
означает «не подошёл», а не падение сервиса.

**Транзакция БД.** Зависимость `current_user` читает; запись делает только
`useradd`. Сессия приходит из `get_session`, как у остальных роутеров.

**Производительность.** bcrypt намеренно медленный (~0,25 с на проверку): это и
есть защита от подбора. На входе это заметно, на остальных вызовах — нет.

**Интеграция.** Убраны свойства `can_*` у модели пользователя — они не
использовались нигде, и это была вторая копия правила прав. Тест на их
отсутствие стоит вместе с проверкой самой таблицы.

**Что нашлось прогоном.** Тестовое приложение без нашего `lifespan` не
закрывает движок базы: утечка всплыла `ResourceWarning`ом в **чужом** тесте
(архив кейсов), потому что `filterwarnings = ["error"]` роняет прогон там, где
мусор собрал сборщик. Диагноз указывал не туда; лечится тем же `lifespan`.

**Канон.** Карта репозитория пополнилась двумя граблями (одна таблица прав,
приложение без `lifespan`), обзор продукта — строкой про вход и `useradd`.
