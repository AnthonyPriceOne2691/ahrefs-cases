## Ревью рисковых мест

**Почему свежесть — время файла, а не имя.** Имя архива содержит дату сборки, и
повторная сборка того же дня переписывает тот же файл. Сортировка по имени
показала бы «вчерашний» как свежий ровно в тот день, когда пачку пересобрали
дважды.

**Почему «пачки нет» — это 200, а не 404.** Человек, читающий `404`, идёт чинить
выдачу; человек, читающий «пачка ещё не собиралась», идёт собирать кейсы. Код
ответа здесь выбирает следующий шаг, а не описывает состояние диска.

**Порядок маршрутов.** `pack` объявлен выше `/{case_id}/download`, иначе FastAPI
попытается прочесть слово как число и вернёт `422`. Ловушка уже срабатывала на
смете прогона — поэтому про неё помнит тест, а не человек.

**Файл, исчезнувший на ходу.** `stat` после `glob` может не найти файл: пачку
пересобирают прямо сейчас. Такой файл пропускается — выдача не падает из-за
гонки, которой сама не создавала.

**Безопасность (`download_pack`, `FileResponse`).** Путь к файлу не приходит
снаружи вовсе: `_newest_pack` выбирает его из `config.export.output_dir`, а
запрос не несёт ни имени, ни маски. Обхода каталога здесь нет по устройству, а
не по проверке. Право то же, что у библиотеки (`read`), — выдача не слабее
чтения, и без токена оба маршрута отвечают `401` (тест E1).

**Транзакция БД.** Риска нет: оба маршрута в базу не ходят — пачка живёт на
диске, и `SessionDep` им не нужен. Записи поставка не делает вовсе.

**Интеграция (каталог выгрузки в контейнере).** Единственная внешняя связь —
том с `data/out`, общий у API и воркера: воркер собирает архив, API его отдаёт.
Проверено исполнением, а не рассуждением — стек поднят, архив собран прогоном,
скачан по HTTP и открыт: 267 319 байт, пять PDF и `кейсы.csv`. Разъедься этот
том, выдача ответила бы «пачка ещё не собиралась», а не отказом.
