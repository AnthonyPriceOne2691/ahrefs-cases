# Spec: нейминг по ТЗ и выдача ZIP-архивом

Последняя поставка Ф4. После неё фаза закрыта: кейсы уходят пачкой.

## Problem

ТЗ называет формат выдачи прямо — **ZIP-архив**, и называет правило имени файла:
«название сайта + Кейс», для непубличных — «сайт в нише такой-то + Кейс».
Сейчас имя техническое (`example.com.pdf`), а пачки нет вовсе: каждый кейс
собирается отдельной командой.

Есть и второй смысл у архива, записанный в реестре конфликтов (№7): **ревью
черновика ТЗ не предусматривает**, и фактическим предохранителем остаётся
человек, который смотрит ZIP перед публикацией. Значит, архив обязан помогать
смотреть: что внутри, у кого какая группа и кого нельзя называть.

## In scope

- Нейминг по ТЗ в `export/pdf_renderer.filename`: «<название> — Кейс.pdf», где
  название уже учло анонимность.
- `export/archive.py` — сборка ZIP: кейсы пачкой плюс внутренний список
  `кейсы.csv` (домен, группа, файл, можно ли публиковать).
- Команда CLI `pack` — собрать кейсы всех «хороших» и «средних» и положить архив.
- Каждый кейс пачки проходит стоп-лист и сверку чисел: ZIP не обходит проверки,
  он их собирает.

## Out of scope

- **Уведомление в Asana/Telegram** со ссылкой на архив — бонус ТЗ, место ему в
  Ф5 вместе с очередью и алертами.
- Раздача архива по HTTP — тоже Ф5.
- PPTX и DOCX — после MVP по решению заказчика.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | публикуемый проект | файл называется «example.com — Кейс.pdf» |
| E2 | непубликуемый проект | «сайт в нише travel — Кейс.pdf»: домена нет в имени |
| E3 | имя с символами, недопустимыми в файловой системе | вычищены, расширение и слово «Кейс» на месте |
| E4 | пачка из трёх кейсов | один ZIP, внутри три PDF и список `кейсы.csv` |
| E5 | список внутри архива | называет домен, группу, имя файла и «можно публиковать» — человеку, который смотрит архив перед публикацией |
| E6 | кейс с контент-запретом | **не попадает** в архив, и `pack` говорит, какой именно и почему |
| E7 | проекты без кейса (`poor`, нет данных) | в архив не идут, и это видно в отчёте по четырём исходам |
| E8 | два кейса с одинаковым именем | имена в архиве не сталкиваются: второй получает суффикс |
| E9 | повторный `pack` | пересобирает архив целиком и пишет новые версии кейсов |
| E10 | пустая пачка | архив не создаётся, отчёт говорит почему: пустой ZIP выглядит как поломка |

## Non-functional

- Кириллица в именах внутри архива читается на Windows и macOS (UTF-8-флаг).
- Ahrefs не трогается.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- Внутренний список кладётся в архив с доменами всех проектов пачки. Архив —
  внутренний артефакт агентства, но если его перешлют клиенту целиком, список
  покажет чужие домены. Помечен строкой «внутренний список» в первой строке
  файла; убрать его целиком — решение заказчика, когда появится правило
  публикации.
