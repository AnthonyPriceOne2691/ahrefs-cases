# Spec: чтение Google Sheet не останавливает API; цена строки в журнале расхода (Z52)

## Problem

- **Z52, API.** `POST /api/intake/link` зовёт синхронный `read_gsheet`, а тот — `httpx.get` (`intake/gsheet_source.py`),
  прямо в async-обработчике. У API один процесс uvicorn: пока Google отвечает (до таймаута чтения таблицы), стоит
  весь сервис — вход, журнал, карточки у всех шести-семи человек.
- **Z52, журнал расхода.** Колонка `units_ledger.units_per_row` объявлена под заголовок Ahrefs
  `x-api-units-cost-row` («объяснять счёт придётся») и не заполняется ни одной записью: цена строки доходит до
  транспорта в заголовках ответа и дальше теряется.
- **Z52, устаревшие тексты.** `README.md`: «Статус: каркас. Кода нет»; шапка `collect/runner.py`: «чего нет
  намеренно: кэша закрытых месяцев… single-flight».

## In scope

- Чтение таблицы и разбор загруженного файла идут в отдельном потоке (`asyncio.to_thread`): цикл событий API
  отвечает другим запросам, пока Google думает. Отказы приёма — прежние.
- Строка расхода живого ответа несёт цену строки из `x-api-units-cost-row`; нет заголовка — пусто, а не догадка.
  У фикстуры — цена строки по той же модели, что и её units.
- README и шапка `runner.py` говорят, что есть сейчас.

## Out of scope

- Асинхронный клиент Google вместо потока — та же цель большей правкой читателя, которым пользуется и консоль.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| M102 | Чтение Google Sheet идёт секунду; в это время — `GET /api/health` | `health` отвечает быстрее полусекунды; приём таблицы проходит, как прежде («принято 1») |
| M103 | Живой ответ с заголовком `x-api-units-cost-row: 11`; такой же без заголовка | строка расхода: `units_per_row` = 11; без заголовка — пусто |
| M104 | Фикстурный ответ по endpoint'у истории | `units_per_row` = цене строки по модели endpoint'а (та же модель, что даёт units фикстуры) |
