# Decisions: project-deletion-api

- 2026-09-24 · выбрал замок Postgres на всё время задачи (`storage.locks.work_lock` в `workers.jobs._run_guarded`) вместо проверки живости задачи через `workers/reaper.job_state` — потому что при `QUEUE_BACKEND=inline` задачи в RQ нет вовсе и проверка отвечала бы «можно» посреди хвоста; замок держит само соединение задачи и снимается её смертью, Redis в пути запроса удаления не нужен
- 2026-09-24 · выбрал отказ `409` при занятом замке работы (`pg_try_advisory_xact_lock`) вместо ожидания (`pg_advisory_xact_lock`) — потому что прогон на живом ключе идёт часами, и запрос удаления, вставший в очередь за ним, упал бы по таймауту прокси, так и не объяснив, чего ждал
- 2026-09-24 · выбрал сессионный замок на своём движке без пула (`work_lock`: `NullPool`, `AUTOCOMMIT`) вместо соединения из пула приложения — потому что сессионный замок живёт на соединении, и возвращённое в пул соединение унесло бы его в чужой запрос, а транзакция, открытая на все 4 часа потолка задачи (`_JOB_TIMEOUT_SEC`), висела бы «idle in transaction»
- 2026-09-24 · выбрал опознавать кейсы пачки по sha256 содержимого вместо домена из `кейсы.csv` — потому что у двух кампаний одного сайта домен один (правило 18а): удалив одну, пачка по домену оставалась бы «чистой» и отдавала кейс удалённого проекта
- 2026-09-24 · выбрал ключ судьбы удалённого проекта по домену строки журнала вместо новой колонки с прежним номером проекта — потому что колонка значит миграцию на живой базе ради случая «две кампании одного сайта удалены и были в одном прогоне»; этот случай объявлен границей (Z41), а слияние разных доменов в одну судьбу закрыто
- 2026-09-24 · выбрал 409 с текстом, называющим прогон (`_refuse_while_working`), вместо общего «занято» — потому что у двух отказов разные действия: ждать конца прогона с номером N или повторить через минуту, когда задача допишет хвост; на копии базы хвост прогона 1814 занял 0,15 с
- 2026-09-24 · выбрал прогонять сьют на своей копии базы (`cases_delete_tests`) вместо общей дев-базы — потому что первый полный прогон на общей базе совпал с сьютом соседнего worktree: 3 падения и сторож `stand_verdicts_survive_the_suite`: вердикты стенда версии `0.0.0-default` переписаны LIVE → FIXTURE (после прогона FIXTURE у 75 из 75, хотя живые ряды есть у 57 проектов); на копии тот же сьют — 662 passed до правки
