# Spec: графики проекта по HTTP — тот же рисунок, что в PDF

## Problem

Следующий экран Ф6 — карточка проекта с графиками. Рисовать их нечем: эндпоинта
нет, а рисовать на фронте нельзя по решению владельца — **один SVG идёт и в PDF,
и в веб**. Второй рисунок неизбежно разойдётся с первым (сглаживание, шкала,
подписи), и тогда сотрудник и клиент увидят разные кривые одного проекта.

Компоновка «два графика» (динамика трафика; позиции top-10 с вложенным top-3)
сегодня живёт внутри рендерера HTML. Позвать её из API нельзя, не потянув за
собой сборку кейса, а кейс собирается только для «хороших» и «средних» — тогда
как карточка нужна для любого проекта, включая «плохой».

Отдельно: карточка читает ряды источником, заданным **умолчанием обработчика**
(`MetricSource.FIXTURE`). В живом режиме это пустые графики при целой базе.

## In scope

- `GET /api/projects/{id}/charts` — готовые SVG с заголовками. Право `read`.
- Компоновка «два графика» переезжает в модуль рисования и зовётся обоими:
  рендерером PDF и обработчиком запроса. Один рисунок — одно место.
- Полосы окон А и Б на графике берутся из **записанного вердикта**; вердикта
  нет — графики рисуются без полос, а не пропадают.
- Источник рядов выбирается **конфигом**, а не умолчанием обработчика: и в
  графиках, и в карточке (правка L53).

## Out of scope

- **Экран карточки** — следующая поставка (`web-project-card`).
- Тумблер «месяц/квартал/год»: агрегация бесплатна и живёт в `classify.series`,
  но её место — на экране, вместе с переключателем.
- Новые виды графиков: ТЗ называет два, и они уже нарисованы.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | проект с рядами трафика и позиций | два блока: заголовок и SVG в каждом |
| E2 | тот же проект | SVG совпадает с тем, что уходит в PDF, до символа |
| E3 | проект без рядов | пустой список, а не блок с пустыми осями |
| E4 | проект с вердиктом | на рисунке есть полосы окон А и Б |
| E5 | проект без вердикта | графики есть, полос нет |
| E6 | несуществующий проект | `404` с номером |
| E7 | человек без права `read` | `403` |
| E8 | `AHREFS_PROVIDER=live` | и карточка, и графики читают ряды `live`, а не фикстурные |

## Non-functional

- Рисование ничего не покупает: SVG строится по уже собранным точкам.
- Ответ — готовая разметка, а не данные для рисования: у фронта не должно
  появиться второй модели графика.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- SVG отдаётся строкой в JSON. Если карточка начнёт тянуть десяток графиков,
  дешевле станет отдавать их отдельными ресурсами с кэшем; на двух — нет.
