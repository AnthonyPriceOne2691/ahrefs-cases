# Spec: экран загрузки — список, смета, запуск

Третья поставка Ф6 и вторая половина пары «приём + экран».

## Problem

Приём и смета есть по HTTP, но нажать их некому: интерфейс показывает на этом
месте заглушку «экран приезжает следующей поставкой». Люди, которые загружают
списки, — PR-отдел и руководители, и `curl` им не инструмент.

Это первый экран основного сценария целиком: **загрузил → увидел цену →
запустил**. Экраны проектов, кейсов и журнала показывают результат, а этот
запускает работу и тратит деньги — поэтому у него другое главное требование.

**Не дать потратить лишнее.** Прогон стоит units, бюджет заказчика — 10 000 на
первичный прогон, и отказ обязан быть виден **до** нажатия, а не после. Кнопка,
которая позволяет начать прогон, обречённый упереться в квоту, стоит дороже
любой вёрстки.

## In scope

- Раздел «Загрузка» в навигации под правом `run` и маршрут `/intake`.
- Два способа дать список: файл (XLSX или CSV) и ссылка на Google Sheet — ровно
  те, что называет ТЗ.
- Отчёт приёма: принято, создано, обновлено и **отказы с номером строки и
  причиной**, сгруппированные по причине.
- Смета: units, число запросов, что уже собрано, разбивка по схеме, остаток
  квоты и резерв.
- Запуск прогона с экрана. **Кнопка недоступна, если смета говорит «нельзя»** —
  и рядом написано почему, разными словами для «не хватает» и «неизвестно».
- Отказы сервера показываются его текстом: формат файла, закрытая таблица,
  активный прогон (`409`), нехватка права.
- Строка состояния запущенного прогона на самом экране, пока он идёт.
- Vitest на экран: приём, отказы, блокировка кнопки.

## Out of scope

- **Журнал прогонов** экраном — следующая поставка. Здесь видно только тот
  прогон, который запустили сейчас.
- Редактирование списка руками: источник — таблица отдела, а не форма.
- Перетаскивание файла мышью: кнопка выбора закрывает сценарий, а drop-zone
  требует своих состояний и своих тестов.
- Догрузка (`refresh`) и выбор ступени: экран запускает шаг 1, как и кнопка API
  по умолчанию.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | человек с правом `run` | видит раздел «Загрузка» первым в меню |
| E2 | человек без права `run` | раздела нет, адрес `/intake` ведёт на разрешённый экран |
| E3 | выбрал XLSX, приём удался | видит «принято N (создано …, обновлено …)» |
| E4 | в файле битые строки | видит их число, номера строк и причины |
| E5 | файл не того формата | видит текст сервера про формат, а не «что-то пошло не так» |
| E6 | вставил ссылку на Google Sheet | тот же отчёт тем же видом |
| E7 | таблица закрыта | видит причину про доступ |
| E8 | смета посчитана | видит units, запросы, остаток квоты и разбивку по схеме |
| E9 | квоты не хватает | кнопка запуска недоступна, причина с числами видна |
| E10 | остаток неизвестен | кнопка недоступна, причина другая (не «мало квоты») |
| E11 | запуск удался | видит номер прогона и его состояние на экране |
| E12 | прогон уже идёт (`409`) | видит отказ с номером активного прогона |
| E13 | приём прошёл | смета пересчитывается сама: список изменился — цена другая |

## Non-functional

- Ни одного адреса бэкенда в коде: ходим через прокси.
- Узкий экран: вёрстка не рассыпается (DoD Ф6).
- Тёмная тема наравне со светлой — стекло и полотно уже это умеют.
- Поставка укладывается в `max_loc_diff` 800 без waiver.

## Open questions

- Экран запускает шаг 1. Ступени 2 и 3 запускаются отдельно (и стоят денег
  избирательно) — их место на экране прогонов, когда он появится.
