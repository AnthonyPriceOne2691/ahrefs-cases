# Tasks: cycle-by-file

## Mini-spec

**Проблема.** Владелец (25.09.2026) описал путь так: «прикрепил ссылку или файл — логика проанализировала
файл (сколько проектов, все ли правильные, какие пойдут в анализ + предварительная смета) — стартует
прогон, в журнале строка с неактивной кнопкой „скачать кейсы“ — по окончании собираются нужные кейсы и
кнопка активна». У нас было не так в трёх местах: прогон шёл по всей базе («54 из 54» при одном проекте
в файле, пачка — 11 кейсов всей базы), ступени — отдельными строками и кнопками, смета — отдельной кнопкой
и по базе. На вопрос об охвате выбрано: «только проекты файла».

**Решение (сервер).** Приём списка возвращает номера своих проектов. `GET /api/runs/chain/estimate
?projects=…` — смета цикла по ним: шаг 1, шаг 2 и данные под кейс по верхней границе (нынешние кандидаты
среди них и те, за кого шаг 1 заплатит впервые). `POST /api/runs/chain {project_ids}` — не хватает units на
цикл — 409, строка не открывается; иначе строка цикла (ступень `cycle`), а ступени — её дочерние прогоны
под тем же ключом задачи. В журнале видна только строка цикла; она идёт, пока идут ступени (щели между
ступенями для экрана нет — L228 решён устройством). Сборка — только кейсы проектов файла, архив сразу в
`runs/<номер цикла>/`; пачка дня на «Кейсах» не трогается. Неудавшаяся ступень останавливает цикл, и
цикл получает её исход и причину.

**Примеры приёмки.**

- **F1.** Приём списка отдаёт `project_ids`; повторная загрузка того же файла — те же номера.
- **C1.** Смета цикла — по проектам файла (`projects` = 1 при всей базе больше), шаг 2 — верхней границей.
- **C2.** Цикл — одна строка журнала: `cycle`, `done`, «1 из 1»; архив — только кейсы проектов файла; пачка
  дня не создана; в раскрытии — судьбы ступеней с их ступенью.
- **C3.** Не хватает на цикл — 409 словами сметы, строка не открыта.
- **C4.** Шаг 2 упал — строка цикла «упал» с его причиной, `current_stage` = `stage2`, архива нет.
