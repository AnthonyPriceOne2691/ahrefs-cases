# Plan

Класс M. Контекст сборки, образ фронта, компоуз.

## Уроки по затронутым путям (`archive/INDEX.md`)

- **L58/L8** — «локально зелено ≠ зелено» и дев-база, живущая между прогонами:
  контейнер эту разницу и убирает, но сам компоуз обязан быть проверен
  исполнением, а не чтением. Отсюда `artifact_oracle` в STATUS.
- **L24** — переносить чужой рецепт вместе с опорой: раскладка компоуза берётся
  из CRM агентства, но зависимости по здоровью (`service_healthy`,
  `service_completed_successfully`) выписываются явно, а не «как там было».
- **L7** — то, что читает машина, обязано быть полем: адрес api для прокси
  приходит переменной окружения, а не правкой конфига под окружение.

Не применимы: **L23**, **L53**, **L64** — путей отказа HTTP поставка не трогает.

## Шаги

1. `.dockerignore` — контекст без `.venv`, `node_modules`, `.git`, кэшей.
2. `Dockerfile` — дев-стадия питона без `COPY . .`; стадия `web-dev` на `node`.
3. `docker-compose.dev.yml` — сервисы `migrate` и `web`, healthcheck у api,
   именованный том под `node_modules` контейнера.
4. `README.internal.md` — запуск одной командой.
5. Проверка исполнением: сборка, подъём, `/api/health`, экран входа, горячая
   перезагрузка обеих половин.

## Rejected alternatives

- **Один контейнер на всё** — отклонено, потому что api и worker обязаны
  перезапускаться и масштабироваться порознь: прогон идёт часами, и падение
  воркера не должно ронять интерфейс.
- **Ставить node_modules в образ и монтировать исходники поверх** без отдельного
  тома — отклонено, потому что монтирование `./web` накрывает `node_modules`
  контейнера каталогом с macOS-бинарниками, и `esbuild` падает на первой сборке.
- **Гонять миграции из api при старте** — отклонено, потому что api запускается
  в нескольких экземплярах в бою, и каждый начал бы мигрировать базу
  одновременно. Отдельный одноразовый сервис делает это один раз.
- **`depends_on` без условий** — отклонено: «контейнер стартовал» не значит
  «Postgres принимает соединения», и api падал бы на первой попытке.
