## Ревью рисковых мест

**Образ, который никогда не собирался, — обещание, а не механизм.** Компоуз с
api и worker стоял в репозитории с Ф1 и выглядел рабочим; первая же настоящая
сборка показала, что контекста нет, `.venv` уезжает внутрь, а `[dev,export]`
ссылается на несуществующий extra. Отсюда `artifact_oracle` в STATUS: у этой
поставки единственный честный оракул — собрать и поднять.

**Миграции отдельным сервисом, а не шагом старта API.** В бою экземпляров API
несколько, и каждый начал бы мигрировать базу одновременно. `migrate` отрабатывает
один раз, а api и worker ждут его `service_completed_successfully` — это видно
в логе подъёма: api перешёл в `Waiting`, потом в `Healthy`.

**Готовность, а не старт.** `depends_on` без условий означает «контейнер
запущен», и api падал бы на первом соединении с ещё не готовым Postgres. Условия
выписаны явно для всех троих.

**Том под `node_modules`.** Монтирование `./web` накрывает каталог контейнера;
без отдельного тома Linux запускал бы macOS-бинарник esbuild. Проверено
сравнением: `linux-arm64` внутри против `darwin-arm64` снаружи.

**Интеграция.** Появилась новая граница — сеть докера: фронт ходит к api по
имени `api`, а не по `localhost`. Адрес приходит переменной `VITE_API_URL`,
которую `vite.config.ts` уже умел читать, поэтому в коде компонентов адресов
по-прежнему нет. Проверено сквозняком, а не чтением: вход, отправленный на
`:5173`, вернул токен, то есть прокси внутри сети докера дошёл до `api:8000`.
Наружу открыты те же порты, что и раньше (8000 и 5173), так что запуск руками
остаётся возможным и ничего не ломает.

`dev-only-not-a-secret`); они и раньше стояли в файле, гейт секретов их знает по
