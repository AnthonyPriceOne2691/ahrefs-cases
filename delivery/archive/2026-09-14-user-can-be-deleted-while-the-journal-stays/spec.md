# Spec: пользователя можно удалить, журнал при этом остаётся

## Problem

Удаления не было. Причина записана в коде: за учёткой тянутся прогоны и расход,
и стереть её значит потерять, кто их запускал (`runs.started_by`,
`ON DELETE RESTRICT`). Но учётки заводят и по ошибке — опечатка в почте, человек
не вышел на работу, — и такие висят в списке навсегда.

## In scope

- `DELETE /api/users/{id}` под правом `manage_users`: админ и инженер по
  таблице доступа ТЗ.
- **Удаляется только учётка, за которой ничего не числится.** Есть прогоны —
  отказ с числом и с тем, что делать вместо: закрыть вход.
- Себя удалить нельзя; последнего администратора — нельзя.
- На экране: удаление из панели человека, с подтверждением в том же окне.

## Out of scope

- **Перенос прогонов на другого человека.** Это переписывание журнала: тот, кто
  запускал, останется тем, кто запускал.
- **Мягкое удаление.** Оно уже есть и называется «вход закрыт»: учётка в
  списке, войти нельзя, журнал цел.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| E1 | учётка без прогонов | удалена, в списке её нет |
| E2 | учётка с прогонами | отказ 409, названо число прогонов и «закройте вход» |
| E3 | сам себя | отказ: удалять станет некому |
| E4 | последний администратор | отказ той же причиной, что при смене группы |
| E5 | пользователь без `manage_users` | 403 |
| E6 | несуществующий id | 404 |

## Non-functional

- Журнал прогонов после отказа цел: ни одной строки не изменено.
- Причина отказа называет следующий шаг, а не только запрет (L32, L34).
